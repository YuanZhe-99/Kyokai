# 身份与访问

谁可以连接到被控端、凭什么连接，以及被控端如何决定。握手本身见 [protocol.md](protocol.md)；密钥与机密存储见
[security.md](security.md)。

## 密码

| 槽位 | 生命周期 | OPAQUE 记录保存在 |
|---|---|---|
| 临时密码 | 每次引擎启动时以及按需重新生成 | 仅内存 |
| 固定密码 | 由被控端用户设置，可以移除 | 机密存储 |

被控端从不保存、也从不接收密码，只保存 OPAQUE 记录；OPAQUE 服务器密钥（`ServerSetup`）只创建一次并保存在机密存储中。
控制端永远无法得知哪些槽位已设置。

## 保存的密码

控制端可以保存被控端的密码（连接表单上的“记住密码”，`session.connect` 的 `remember`）。只有在被控端接受登录之后才保存，存放在机密存储的 `saved_password.<设备 ID>` 下，与其他机密一样加密，从不显示或返回：状态中只说明哪些最近设备保存了密码（`saved_password`，以及 `saved` 中每种已保存登录方式的标志）。之后密码栏留空时就使用它。被控端拒绝保存的密码（密码已更改）时，控制端会忘记它。为被控端保存的其他内容——它接受过的登录密钥（见“密钥”）以及其服务的登录信息（[remote-services.md](remote-services.md)）——保存在 `saved.<设备 ID>` 下；最近设备一行上的“忘记密码”（`password.forget_saved`）与移除设备都会同时忘记这两者。

## 密钥

SSH 风格的 Ed25519 密钥可以不用密码登录 Kyokai（[protocol.md](protocol.md)，“密钥登录”）。

- **可连接的密钥**（被控端，机密存储中的 `authorized_keys`，最多 32 个）：OpenSSH 公钥行（`ssh-ed25519 AAAA… 注释`），
  每个都有名称（未指定时取注释）、添加时间与最近一次登录时间；其他类型的密钥会被拒绝（`authorized.list`、`authorized.add`、
  `authorized.remove`）。
- **本机的密钥**（控制端，`login_keys`，最多 16 个）：Ed25519 密钥用于登录 Kyokai；Ed25519、RSA（2048 位及以上）以及 ECDSA
  P-256 或 P-384 密钥通过内置客户端登录 SSH 服务器。界面生成或导入密钥，并把私钥部分（Ed25519 种子或 PKCS#8 DER）一次性交给
  引擎（`keys.add`）；引擎检查它，把它保存在机密存储中，并且从不返回：`keys.list` 只回答名称、类型与公钥行。同一把密钥只保存
  一次：它的 ID 是其公钥 SHA-256 的前 16 个十六进制数字。
- 控制端只向声明了 `key-login` 的被控端提供密钥，续接时从不提供：先提供该被控端上次接受的密钥，否则提供每一把 Ed25519 密钥
  （最多 8 把）。被控端以第一把证明成立的可连接密钥接入；它不认识的密钥被忽略，证明不成立的可连接密钥计为一次登录失败。
- 密钥与固定密码同等对待：只要“无需确认即可连接”开启，无论接受哪些密码，它都能在密码授予的权限范围内接入，在无人值守时也一样
  （见“无人值守访问”）；它从不关闭保护模式。请求更多权限时，会询问被控端用户，用户会看到该密钥的名称。
- 控制端记住被控端接受的密钥，下次先提供这一把，其余密钥随后（被控端不再接受它时，仍能找到它接受的那一把）；被控端以其他方式接入时，就忘记它。输入的密码只有在被控端凭它接入时才保存。
- `keys.sign`（`{key_id, algorithm, data}`）只为那一把密钥签署 SSH 公钥用户认证请求（RFC 4252 第 7 节），算法按密钥类型为
  `ssh-ed25519`、`rsa-sha2-256`、`rsa-sha2-512`、`ecdsa-sha2-nistp256` 或 `ecdsa-sha2-nistp384`，并回答 SSH 签名（string
  format、string blob；base64）；其他一切都会被拒绝，因此引擎不是通用的签名服务。只为引擎的所有者或助手的操作者提供，从不为
  `kyokai` 组提供。

## 权限

`view-screen`、`control-input`、`run-ai-task`、`approve-ai-action`、`clipboard`、`files`（通过剪贴板复制文件；`clipboard` 不包含它）、`hear-sound`（被控端的声音；`view-screen` 不包含它）、`see-status`（静默查看被控端的状态，[computer-use.md](computer-use.md)，“被控端状态”），以及 `use-ssh`、`use-rdp` 与 `use-vnc`（通往被控端自身 SSH、远程桌面或 VNC 的隧道，[remote-services.md](remote-services.md)）。控制端请求一组权限；被控端用户授予其中
的子集；任何权限都不隐含另一个。加入网络本身不授予任何权限。`run-ai-task` 允许控制端在被控端上启动 AI 任务（使用被控端的密钥运行），并控制被控端的任务，无论由谁发起（被控端为所有控制端保留同一份 AI 记录）；
`approve-ai-action` 允许它答复该任务的批准请求（[computer-use.md](computer-use.md)）。移除受信任设备会立即撤销它：它与本机的进行中会话结束，续接令牌被丢弃。

## 准入

| 控制端 | 被控端 |
|---|---|
| 给出被接受的正确密码，且只请求密码授予的权限 | 立即接受，授予它请求的权限（“无需确认即可连接”开启时） |
| 给出正确密码，但请求更多 | 请它的用户确认 |
| 给出正确密码，但用的是冒用另一把密钥下受信任设备 ID 的新密钥 | 请它的用户确认 |
| 证明一把可连接的密钥，且只请求密码授予的权限 | 立即接受，授予它请求的权限（“无需确认即可连接”开启时） |
| 证明一把可连接的密钥，但证明不成立 | 按密码错误拒绝 |
| 以授予范围内的密码或密钥查看状态 | 立即接受（“无需确认即可连接”开启时）；从不询问：其他情况一律以 `denied` 拒绝 |
| 不使用密码而请求 | 请它的用户确认；被拒绝或无人回应计为一次登录失败 |
| 在无人值守时给出固定密码 | 接受，授予密码可授予的权限（见“无人值守访问”） |
| 给出被控端不接受的那类正确密码 | 按密码错误拒绝 |

哪些密码可以打开被控端，在“权限”中选择（“接受的密码”：临时密码、固定密码或两者，默认两者）；“无需确认即可连接”（默认开启）让被接受的密码无需确认即可接入，关闭后每次连接都会询问。密码无需确认即可授予哪些权限也在那里选择（“使用正确密码时”），每个权限一个开关，保存在机密存储中：默认是 `view-screen`、
`control-input`、`clipboard`、`files`、`hear-sound`（控制端默认也请求这些）与 `see-status`；AI 权限与各项服务始终需要确认，除非在那里打开。旧版本保存了授予的权限的被控端，会在启动时一次性获得新权限的默认值（`password_grants_known` 记录所保存的授予是基于哪些权限选择的）：`see-status` 打开，各项服务关闭。

## 被控端确认

被控端用户会看到控制端的别名与设备 ID、它的密钥是否已知、它是否没有使用密码、它所证明的登录密钥的名称、它请求的权限以及隧道的服务，并在 60 秒内允许（选择权限）或拒绝。
不作回应即视为拒绝。每个控制端密钥最多同时有一个确认，总数最多 4 个；更多的尝试以 `busy` 答复。

## 固定的密钥

- **被控端（受信任设备）：** 被接受的控制端设备密钥会连同其设备 ID、首次与最近连接时间以及最近授予的权限一起记录。
  若某个设备 ID 已以另一把密钥被记录，控制端会显示为“冒用此 ID 的新密钥”。
- **控制端（已知被控端）：** 第一次被接受的会话会为该设备 ID 固定被控端的设备密钥；之后密钥不同的会话会被拒绝，直到用户
  忘记该被控端。每次被接受的会话还会记录时间，并把所拨打的地址加入该被控端的路径
  （[networking.md](networking.md)，“路径”：地址只是寻找设备的地方；在那里应答的另一台设备会像任何冒用者一样无法通过握手），
  最近的 8 个作为最近设备提供。按地址连接时，
  用户没有指定设备 ID：第一次会话固定在那里应答的设备，其设备 ID 显示在标签页与“最近”中。每次被接受的会话还会记录被控端声明的内容
  （`features`），状态会把它传下去（`recent[].features`），这样主页在拨号之前就知道被控端提供什么。移除一台最近设备会忘记其
  固定的密钥与为它保存的一切，并把它的会话移出列表。
- **完全无日志**只在内存中保留这两份列表（[security.md](security.md)）：重启后没有固定的密钥，因此不会发现密钥的变化。

## 别名

每台设备都有一个别名，在“安全”中设定（设备身份；最多 64 个字符；留空则使用电脑的名称：Windows 上为 `COMPUTERNAME`，macOS 上为“共享”中的名称），
保存在状态文件夹的 `device.json` 中。设备会连同别名一起说明它的硬件厂商与型号（Windows 上为 SMBIOS 的 `SystemManufacturer` 与
`SystemProductName`；macOS 上为 Apple 与 `hw.model`）以及它的系统。控制端在 `login` 中发送这份说明，被控端在表示接受的 `verdict` 中发送
（[protocol.md](protocol.md)），因此在密码检查之前不会有任何内容到达对方，EasyTier 主机名也仍是 `Kyokai-<设备 ID>`。收到的说明会被清理
（去掉控制字符与双向覆盖字符，每个字段截断为 64 个字符），并随受信任设备（被控端）或已知被控端（控制端）保存；恢复的会话沿用上一次的说明。
它只是对方设备的说法：界面总是把它显示在设备 ID 旁边，而不是代替设备 ID，它也不用于任何认证。用户也可以给设备起一个自己的名称
（“最近”中的“重命名…”），它只保存在本机界面的设置中，代替设备的别名显示，同样显示在设备 ID 旁边。

## 保护模式

“安全”中的**保护模式**（默认关闭）让这台电脑上的 Kyokai 只提供 AI 设置和 AI 任务，适用于本地用户应当运行 AI 任务但不能更改其他任何内容的电脑。
只有设置了固定密码时才能打开（需确认），也只能用该密码关闭（在 AI 页面输入）：核心在本机上对固定密码记录运行 OPAQUE 登录的双方来检查它
（`Slots::check_permanent`；临时密码不算），并且在此模式打开时拒绝移除固定密码。这一选择（`protected`）保存在机密存储中，因此重启后仍然有效，
并随存储迁移。引擎在本地 API 上强制执行它，所以 `ctl` 也同样受限：打开期间只服务状态、AI 请求、答复确认、断开连接、退出、关闭此模式，以及界面
在连接时发送的内容（采集、声音、完全无日志、隐私权限、助手更新）。被控端用户仍然掌控一切：确认请求与已连接到本机的设备仍显示在每个页面上。

## 身份备份、恢复与重置

备份包含设备密钥、OPAQUE 服务器密钥与固定密码记录、受信任设备以及已知被控端，以 JSON 形式用 XChaCha20-Poly1305 加密，密钥由
Argon2id（64 MiB、3 轮）从至少 10 个字符的口令派生。恢复会先完整检查文件再写入；重置会忘记上述全部内容，从而得到新的设备 ID。
两者都会立即重建核心：会话结束，网络重新连接。网络设置不属于身份。

## 无人值守访问

没有人在这台电脑前时——后台服务模式的助手且没有连接界面——只要“无需确认即可连接”开启，固定密码或一把可连接的密钥即可让设备无需确认地接入，获得其请求范围内密码可授予的权限；临时密码、不带密码的请求，以及冒用受信任设备 ID 的新密钥都找不到人确认。后台服务本身需要明确选择（安装助手需要一次管理员提示），因此只有用户这样设置时，电脑才处于无人值守状态。

被控端服务谁取决于它的运行方式（[run-modes.md](run-modes.md)）：免授权模式下以及有界面连接到助手时服务所有人；没有界面时，后台服务模式的助手只服务固定密码与密钥，随界面模式的助手不服务任何人（其被控会话会结束）。无人能确认的登录会立即以 `absent` 拒绝；不服务任何人时，在检查密码之前就会拒绝。

## 速率限制

| 限制 | 数值 |
|---|---|
| 每个来源地址的登录失败 | 10 分钟内 5 次，之后该地址被拒绝 10 分钟；不使用密码的请求被拒绝或无人回应时计为一次 |
| 全部登录失败 | 一分钟内超过 20 次时，所有未固定的控制端需等待 30 秒；已固定的密钥不受影响，因此猜测无法把真正的用户挡在门外 |
| 处于握手或登录中的传入连接 | 同时 16 个；更多的会被丢弃 |
| 被控端上已连接的会话 | 同时 4 个（每个都可能占用一个采集与一个编码器）；更多的会以忙为由被拒绝 |
| 被控端上的隧道 | 在桌面会话之外同时 8 条；更多的会以忙为由被拒绝 |
| 被控端上的状态查看者 | 在其他会话之外同时 16 个；更多的会以忙为由被拒绝 |
| 等待中的被控端确认 | 4 个；更多的会以忙为由被拒绝 |

限制按来源虚拟地址计算，因为在被固定之前，密钥可以零成本生成：按网络和地址计算，因为 EasyTier 的地址范围在各个网络中重复，一个网络里的
猜测不能把另一个网络中的设备锁在外面（按地址连接算作一个单独的网络）。
