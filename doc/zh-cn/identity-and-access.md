# 身份与访问

谁可以连接到被控端、凭什么连接，以及被控端如何决定。握手本身见 [protocol.md](protocol.md)；密钥与机密存储见
[security.md](security.md)。

## 密码

| 槽位 | 生命周期 | OPAQUE 记录保存在 |
|---|---|---|
| 临时密码 | 每次引擎启动时以及按需重新生成 | 仅内存 |
| 固定密码 | 由被控端用户设置，可以移除 | 机密存储 |

被控端从不保存、也从不接收密码，只保存 OPAQUE 记录；OPAQUE 服务器密钥（`ServerSetup`）只创建一次并保存在机密存储中。
控制端永远无法得知哪些槽位已设置。

## 权限

`view-screen`、`control-input`、`run-ai-task`、`approve-ai-action`、`clipboard`、`files`（通过剪贴板复制文件；`clipboard` 不包含它）。控制端请求一组权限；被控端用户授予其中
的子集；任何权限都不隐含另一个。加入网络本身不授予任何权限。`run-ai-task` 允许控制端在被控端上启动并控制自己的 AI 任务（使用被控端的密钥运行）；
`approve-ai-action` 允许它答复这些任务的批准请求（[computer-use.md](computer-use.md)）。移除受信任设备会立即撤销它：它与本机的进行中会话结束，续接令牌被丢弃。

## 准入

| 控制端 | 被控端 |
|---|---|
| 给出正确密码，且只请求密码授予的权限 | 立即接受，授予它请求的权限 |
| 给出正确密码，但请求更多 | 请它的用户确认 |
| 给出正确密码，但用的是冒用另一把密钥下受信任设备 ID 的新密钥 | 请它的用户确认 |
| 不使用密码而请求 | 请它的用户确认；被拒绝或无人回应计为一次登录失败 |
| 持有无人值守授权并给出固定密码 | 立即接受（见下文） |

密码无需确认即可授予哪些权限，在设置、访问（“使用正确密码时”）中选择，每个权限一个开关，保存在机密存储中：默认是 `view-screen`、
`control-input`、`clipboard` 与 `files`；AI 权限始终需要确认，除非在那里打开。

## 被控端确认

被控端用户会看到控制端的别名与设备 ID、它的密钥是否已知、它是否没有使用密码，以及它请求的权限，并在 60 秒内允许（选择权限）或拒绝。
不作回应即视为拒绝。每个控制端密钥最多同时有一个确认，总数最多 4 个；更多的尝试以 `busy` 答复。

## 固定的密钥

- **被控端（受信任设备）：** 被接受的控制端设备密钥会连同其设备 ID、首次与最近连接时间以及最近授予的权限一起记录。
  若某个设备 ID 已以另一把密钥被记录，控制端会显示为“冒用此 ID 的新密钥”。
- **控制端（已知被控端）：** 第一次被接受的会话会为该设备 ID 固定被控端的设备密钥；之后密钥不同的会话会被拒绝，直到用户
  忘记该被控端。每次被接受的会话还会记录时间，最近的 8 个作为最近设备提供。

## 别名

每台设备都有一个别名，在设置中设定（设备身份；最多 64 个字符；留空则使用电脑的名称：Windows 上为 `COMPUTERNAME`，macOS 上为“共享”中的名称），
保存在状态文件夹的 `device.json` 中。设备会连同别名一起说明它的硬件厂商与型号（Windows 上为 SMBIOS 的 `SystemManufacturer` 与
`SystemProductName`；macOS 上为 Apple 与 `hw.model`）以及它的系统。控制端在 `login` 中发送这份说明，被控端在表示接受的 `verdict` 中发送
（[protocol.md](protocol.md)），因此在密码检查之前不会有任何内容到达对方，EasyTier 主机名也仍是 `Kyokai-<设备 ID>`。收到的说明会被清理
（去掉控制字符与双向覆盖字符，每个字段截断为 64 个字符），并随受信任设备（被控端）或已知被控端（控制端）保存；恢复的会话沿用上一次的说明。
它只是对方设备的说法：界面总是把它显示在设备 ID 旁边，而不是代替设备 ID，它也不用于任何认证。

## 身份备份、恢复与重置

备份包含设备密钥、OPAQUE 服务器密钥与固定密码记录、受信任设备以及已知被控端，以 JSON 形式用 XChaCha20-Poly1305 加密，密钥由
Argon2id（64 MiB、3 轮）从至少 10 个字符的口令派生。恢复会先完整检查文件再写入；重置会忘记上述全部内容，从而得到新的设备 ID。
两者都会立即重建核心：会话结束，网络重新连接。网络设置不属于身份。

## 无人值守访问

被控端用户可以让某个受信任设备在 30 天内无需确认即可连接（设置、访问：“无需确认即可连接”；通过本地 API 最多 365 天）。这种登录需要该设备
已固定的密钥**以及**固定密码（临时密码始终需要确认），获得之前授予该设备、且在其请求范围内的权限，授权到期或被关闭后即停止。默认关闭。
没有无人值守授权时，只有在密码授予的权限之内的正确密码可以跳过确认（见“准入”）。

被控端服务谁取决于它的运行方式（[run-modes.md](run-modes.md)）：免授权模式下以及有界面连接到助手时服务所有人；没有界面时，后台服务模式的助手
只服务无人值守授权，随界面模式的助手不服务任何人（其被控会话会结束）。无人能确认的登录会立即以 `absent` 拒绝；不服务任何人时，在检查密码之前就会拒绝；密码授予的权限只在服务所有人时生效。

## 速率限制

| 限制 | 数值 |
|---|---|
| 每个来源地址的登录失败 | 10 分钟内 5 次，之后该地址被拒绝 10 分钟；不使用密码的请求被拒绝或无人回应时计为一次 |
| 全部登录失败 | 一分钟内超过 20 次时，所有未固定的控制端需等待 30 秒；已固定的密钥不受影响，因此猜测无法把真正的用户挡在门外 |
| 处于握手或登录中的传入连接 | 同时 16 个；更多的会被丢弃 |
| 被控端上已连接的会话 | 同时 4 个（每个都可能占用一个采集与一个编码器）；更多的会以忙为由被拒绝 |
| 等待中的被控端确认 | 4 个；更多的会以忙为由被拒绝 |

限制按来源虚拟地址计算，因为在被固定之前，密钥可以零成本生成。
