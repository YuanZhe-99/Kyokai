# 电脑操作

控制端如何看到并操作被控端。本页随 Phase 3（手动控制）与 Phase 4（AI）逐步补充。

## 视频

| 阶段 | 位置 | 内容 |
|---|---|---|
| 采集 | 被控端引擎 | 通过 RustDesk 的 DXGI 桌面复制采集主显示器（`core/third_party/rustdesk-dxgi`）；屏幕静止时不产生帧 |
| 缩放与转换 | 被控端引擎 | BGRA 转为 NV12（BT.601，有限范围），缩小到 1920×1080 以内，边长为偶数 |
| 编码 | 被控端引擎 | 通过 Media Foundation 的同步 Microsoft 编码器编码 H.264：低延迟（在设置媒体类型之前设置；第一帧之后就有输出）、CBR 4 Mbit/s、无 B 帧、每 4 秒及按需生成关键帧；30 fps |
| 传输 | 会话 | 媒体分片在 Noise 通道中传输（[protocol.md](protocol.md)）；会话忙时生产者会等待，因此采集速度与网络的接收速度一致 |
| 转发 | 控制端引擎 | 会话的媒体队列（保留最新 3 帧）→ 本地 API 的 `session.media` |
| 解码 | 界面 | 界面自己加载的核心（`kyokai_decoder_*`）：低延迟模式下 Media Foundation 的 H.264 解码器，NV12 转为 RGBA，并裁剪为视频流的尺寸 |
| 显示 | 界面 | 查看窗口的位图，两幅画面交替使用 |

有帧滞留在编码器中时，被控端会重复上一幅画面，使其在屏幕静止时也能输出。无法采集的被控端（没有交互式桌面，例如服务或
SSH 会话）或没有 H.264 编码器的被控端（Windows N、未安装 Media Foundation 的 Server 版）会改为发送 320×180 的测试图案（`raw-rgba`）。

查看窗口打开时会请求关键帧；被控端随即重新描述视频流并开始新的图像组。
