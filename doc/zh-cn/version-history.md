# 版本历史

## 0.6.5（2026-10-28）

- Mac 上登录时打开的 Kyokai 即使打开了“登录时启动后隐藏到托盘”也会显示窗口：MyGo 在
  `applicationWillFinishLaunching:` 中读取说明应用作为登录项打开的启动 Apple 事件，那时 AppKit 还没有分派它，
  所以总是回答“否”。Kyokai 现在在 AppKit 处理该事件时、于其启动代码运行的 `applicationDidFinishLaunching:` 中
  自己读取。尚未在 Mac 上登录确认。
- “关于与更新”新增“自动安装更新”：从不（默认）、电脑空闲时（15 分钟无人使用），或每天定时到所选整点（默认 03:00）。
  只在没有会话、连接请求、AI 任务或活动的小窗时安装找到的更新；某个版本安装失败后直到下次启动才重试；窗口原来隐藏时
  重启后回到托盘。
- 上游：MyGo v0.7.1，无需界面迁移。已检查，未变：EasyTier v2.7.0、RustDesk 1.5.0（复用代码）、vcpkg 2026.10.16、
  Rust 1.99.1。ABI 7、协议 10 与本地 API 2 不变。

- 上游已检查，未变：MyGo v0.6.4、EasyTier v2.7.0、RustDesk 1.5.0（复用代码）、vcpkg 2026.10.16、Rust 1.99.1。ABI 7、协议 10 与本地 API 2 不变。

## 0.6.3（2026-10-25）

- Mac 被控端可能一直显示“本设备无法显示那边的电脑发送的画面”，直到关闭并重新打开小窗：被控端等待控制端编解码器的一秒，到期之后，每当恢复步骤关闭视频就再次生效，视频随之像对不说明编解码器的控制端那样在主显示器上打开——在 Mac 上没有可用的编解码器，于是一直是“没有共同的编解码器”占位画面；在 Windows 上则是 H.264，不管查看窗口选了什么。现在只等待一次，恢复时以控制端的编解码器重新打开视频。
- 被控端不会再尝试时（没有共同的编解码器、屏幕无法共享），或 10 秒没有显示其屏幕的画面时，画面区域提供“重新连接”。
- 主页的设备状态不再在每次显示主页时重新连接：主窗口打开期间，主页的被控端保持被查看，主页隐藏时每 5 秒、显示时每 2 秒；关闭窗口才结束查看。查看者把速度告诉被控端（`pace`；较旧的被控端忽略它，仍为 2 秒），所有查看者都要求慢速时被控端每 5 秒采样一次。
- 上游：MyGo v0.6.4（Go 1.27.3），无需界面迁移。已检查，未变：EasyTier v2.7.0、RustDesk 1.5.0（复用代码）、vcpkg 2026.10.16、Rust 1.99.1。ABI 7、协议 10 与本地 API 2 不变（`watch.set` 接受 `slow`，较旧的引擎忽略它）。

## 0.6.2（2026-10-24）

- 有连接时关闭主窗口，只有部分连接随之收到托盘：关闭只结束了隔一个的连接，留下的连接重绘已结束的窗口，导致程序崩溃（0.6.0 引入的回归，各系统都有）。现在每个连接都会关闭，Kyokai 留在托盘中。
- 指针位于小窗内任何位置——标题栏、控制栏、剪贴板面板或画面——键盘抓取都保持；小窗的菜单或分屏列表、设置、搜索或 + 选择器打开时让开（0.6.1 及以前，抓取在画面边缘就结束）。
- 映射与翻译不再因抓取放过按键而丢键：这样的按键按传统模式发送，并重新持有抓取；窗口重新激活、指针回到小窗、核心报告抓取已停止时也会重新持有（macOS：重新打开或新建事件监听；Windows：重新安装钩子，因为 Windows 会悄悄移除处理过慢的钩子）。在 Mac 上，映射与翻译曾时而只发送字母，直到重启 Kyokai。
- macOS：每个事件监听用自己的句柄重新打开自己；在运行循环运行之前发出的停止不再丢失。
- 控制栏键盘图标下方的两个点：Kyokai 持有键盘；按键到达抓取（未到达时为琥珀色并说明原因——例如另一个应用开启了安全键盘输入）。界面日志记录抓取放过按键的时间与原因。
- 核心：clipboard-win 5.4.3（5.4.1 已被撤回）；忽略 RUSTSEC-2026-0387（经 opaque-ke 的 elliptic-curve 0.13 引入的 crypto-bigint 0.5），因为 OPAQUE 套件用的是 Ristretto255。
- ABI 7（`kyokai_keyboard_state`；再次请求抓取时 `kyokai_keyboard_grab` 重新持有它）；协议 10 与本地 API 2 不变。上游版本已检查，未变：MyGo v0.6.3、EasyTier v2.7.0、RustDesk 1.5.0（复用代码）、vcpkg 2026.10.16、Rust 1.99.1。

- macOS：主窗口的红绿灯离窗口边缘 9 点，与系统自己的窗口相同，位于 72 点宽的图标栏之上；受保护模式为它们留出位置。
- SSH 每次都打开一个新的小窗，因此一台设备可以同时开多个终端（SSH 2、SSH 3）。
- 修复：SSH 连接拒绝出示另一个服务器密钥的重新协商；停止引擎的本地 API 时不再与其连接发生竞争（CI 中出现过一次崩溃）。
- Go：purego 0.11.2；核心：libc 0.2.191。
- 协议 10、本地 API 2 与 ABI 6 不变。上游版本已检查，未变：MyGo v0.6.3、EasyTier v2.7.0、RustDesk 1.5.0（复用代码）、vcpkg 2026.10.16、Rust 1.99.1。

## 0.6.0（2026-10-23）

- 全新的界面。侧边栏位于窗口的材质之上，列出主页与每个打开的小窗——桌面、SSH、远程桌面、VNC、被控端的状态或 AI 会话——小窗以圆角浮在它旁边。小窗可以向右或向下分屏（每组最多四个），一个分组在侧边栏中显示为一个条目，拖出去的小窗会得到独立窗口。每个小窗都有同样的标题栏；窄的标题栏把按钮收进 ⋯。在 Windows 上，窗口按钮由界面绘制在右上角小窗标题栏的末端。
- + 打开选择器：先选类型（桌面、SSH、远程桌面、VNC 或 AI 任务），再按名称、设备 ID 或地址选设备，不提供该类型的设备变灰并说明原因。Ctrl+K（⌘K）搜索设备、打开的小窗、设置与操作。
- 设置是覆盖整个窗口的面板：分组的部分带搜索，每行是一个标题、一句话与它的控件，较长的说明在 ⓘ 后面，密码授予的权限以图块显示。
- 主页：“本机”与“连接到设备”并排，“打开为”（桌面、SSH、远程桌面、VNC 或 AI 任务），设备以等高的卡片显示并带四项实时数据；“我的网络中的其他设备”加入已加入的网络能到达的 Kyokai 设备。
- AI 会话是小窗，每台设备可以有多个，各自可以重命名：对话中的步骤按回复分组，批准就地进行，输入框使用你选择的发送键，并显示批准方式、在哪里运行以及使用谁的密钥的模型；最近的任务包括本机的与和其他设备的会话。被控端的 AI 通过单独的链接运行，只请求运行 AI 任务与批准其操作。AI 页面取消；服务商仍在设置 › AI 中。
- 需要你处理的事情以卡片显示在小窗上方：连接请求——它请求的权限以图块显示，可以在“允许”之前关掉——、连接到本机的设备、在本机等待或工作的 AI 任务。保护模式、“正在启动…”与引擎未运行也都在新界面中。
- 两种外观下文字都达到 WCAG AA 的对比度，一切都能用键盘操作。
- 核心：ctutils 0.4.5（RUSTSEC-2026-0385）。
- 协议 10、本地 API 2 与 ABI 6，均未改变。上游版本：MyGo v0.6.3（原为 v0.6.2）、EasyTier v2.7.0、RustDesk 1.5.0（内置的代码）、vcpkg 2026.10.16、Rust 1.99.1。

## 0.5.5（2026-10-23）

- Mac 控制端重新能发送每个按键（0.5.4 引入的回归）。它的事件监听还要求按键位置处的窗口属于 Kyokai，并从屏幕上的整个
  窗口列表中读取，而其中其他程序与系统的不可见窗口盖住了 Kyokai 的窗口；查看窗口以为自己在抓取时，事件监听却放行了所有
  按键，于是除非指针在画面之外，Enter、Tab、Delete、Shift 与 Command 都到不了被控端（字母与数字作为文字到达）。事件监听
  重新只要求 Kyokai 拥有最前面的窗口，查看窗口在指针位于画面上方时抓取；Windows 仍检查指针处的窗口。
- 关闭的标签页不再回来：关闭标签页或窗口曾立即为同一设备打开一个新的标签页，显示会话已结束（自 0.5.0 起），因为引擎在
  发送告别期间仍让正在关闭的会话保持连接。界面不会为自己关闭的会话打开标签页，直到该会话结束。
- 控制端的输入法在远程画面中关闭，每种键盘模式下都是如此，远程桌面与 VNC 的画面也一样：中文与日文用被控端自己的输入法
  输入，在那边打开它，并使用映射模式。翻译模式把在控制端键盘布局上产生字符的按键作为其文字发送，其他按键按位置发送，
  不扣留任何按键（以前在中文、日文或韩文布局上，字母之后最多一秒内会扣留编辑键，这期间输入的 Enter 可能丢失）；抓取的
  `pass` 模式已移除。
- CI：编解码库从缓存的安装树取得，不再经过 vcpkg（运行器镜像一换编译器，它的二进制缓存就会错过）；clippy 与
  Rust 测试与其他任务并行；CI 的安装包直接使用构建好的核心；运行器镜像自带的 Rust 不再改变 Rust 缓存的键；Mac
  发布在同一次 cargo 运行中构建两个核心。
- 协议 10 与本地 API 2 不变；ABI 6（`kyokai_keyboard_grab` 不再接受 `pass`）。上游版本：MyGo v0.6.2、EasyTier v2.7.0、
  RustDesk 1.5.0（内置代码）、vcpkg 2026.10.16、Rust 1.99.1，已检查，未变。

## 0.5.4（2026-10-22）

- 慢速路径：被控端等待迟到的确认，不再在 3 秒后把帧视为丢失——那会往一条还没送达上几帧的路径上发送更多帧与一个新的
  关键帧；在每秒几百 kbit 的路径上，延迟增长到数秒，画面冻结，输入暂停，会话大约每 25 秒断开一次。最多 3 帧未确认；
  关键帧请求或查看窗口的 `no-picture` 会等待仍在途中的关键帧。
- 会话的写入器：输入、确认、ping 与被控端的统计排在等待中的视频之前发出，并且无论视频如何都会被读取；文件内容等待空位。
- 键盘跟随指针：在映射与翻译模式下，指针下方的画面接收按键与文字焦点，分屏时也是如此；指针上方的其他程序窗口会把按键
  取回。只有持有窗口抓取的标签页才能结束它（切换标签页曾使只有文字到达被控端：没有 Tab、Enter、Delete 或 Shift）。
- 正在连接或等待设备用户时关闭的连接会立即结束（以前它会继续，在标签页关闭后连上，并以单独的标签页再出现，显示会话已结束）。
- `ctl watch` 每秒打印被控端测得的延迟。
- 协议 10、ABI 5 与本地 API 2 不变。上游版本：MyGo v0.6.2、EasyTier v2.7.0、RustDesk 1.5.0（内置代码）、vcpkg 2026.10.16、
  Rust 1.99.1，已检查，未变。

## 0.5.3（2026-10-22）

- 被控端显示器黑屏后画面会恢复，适用于所有平台。Windows 上的主要原因：GPU 的编码器（高通）在显示器
  关闭时没有任何输出，显示器重新点亮后仍然没有输出，而 Kyokai 把它当成了静止的画面。现在编码器 2 秒
  没有输出即算失败；只在显示器开启时使用 GPU 的编码器（先唤醒），否则使用软件编码器；第一次查看会
  等待 Windows 对显示器状态的报告。
- 被控端从不放弃画面：它会重新打开视频、尝试下一个编码，然后在继续重试真实屏幕的同时显示状态说明，
  画面恢复后重新计数。控制端显示被控端报告的状态（屏幕已休眠正在唤醒、Kyokai Helper 正在准备、画面
  正在重新开始），不再显示彩条，并在对方屏幕变黑时提供唤醒。macOS 上采集前会唤醒休眠的显示器，显示器
  休眠后声音会重新开始。
- Kyokai Helper：界面连接时不再重启会话代理并中断画面；代理不在时请求的唤醒会发给下一个代理；它的
  日志（包括 macOS 代理的）不需管理员权限即可通过诊断中的保存日志保存（`ctl logs`）。
- Windows 登录时不再出现白色窗口：主窗口只在显示时存在；在托盘中启动时不创建窗口，关闭到托盘时窗口
  随之结束。
- 分屏：把标签页拖到某个画面上，即显示在那个画面的旁边、上方或下方——一个窗口中最多四个标签页，可
  任意排列；焦点所在的标签页接收键盘与剪贴板。
- 协议 10 与 ABI 5 不变，新增功能标记 `recovery`；本地 API 2 新增 `logs.read`，旧版引擎会拒绝。上游
  版本：MyGo v0.6.2、EasyTier v2.7.0、RustDesk 1.5.0（内置代码）、vcpkg 2026.10.16、Rust 1.99.1，
  已检查，未变。

## 0.5.2 (2026-10-22)

- 被控端变暗的显示器无论是否锁屏都能唤醒：Windows 报告控制台显示器已关闭时被控端也会唤醒它（变暗的显示器和静止的屏幕一样不发送任何东西，
  因此会话中途变暗的显示器从未被唤醒），并在接收输入的桌面上用绝对坐标的指针移动来唤醒（一像素的相对移动可能毫无效果）。
- “唤醒”按钮生效：它现在是被控端的 `wake` 会话操作，立即唤醒显示器并请求关键帧；以前它是一次 Shift 按下，在 Kyokai 窗口拥有焦点时
  会被“远程输入不触及 Kyokai 窗口”的防护丢弃。0.5.1 及更早的被控端仍收到 Shift 按下。睡眠与休眠（包括现代待机）依然无法远程唤醒：Windows 会断开网络。
- 保存的密码与密钥：可以单独忘记为某设备保存的 Kyokai 密码（以前会被拒绝，只有“全部忘记”能删除它）。
- 权限：“密码与密钥”包含固定密码和登录方式——临时密码、固定密码以及每个可连接的密钥各有一个复选框，可任意组合；一项都不勾选时每次连接都会询问。
  可连接本设备的密钥从“安全”移到了这里；关闭的密钥会保留，但不能让任何设备登录。
- 协议 10 与 ABI 5 不变，新增功能标记 `wake`；本地 API 2 新增 `authorized.set`、密钥的 `off` 与密码方式 `none`，较旧的引擎不认识它们
  （从存储中读到 `none` 的旧引擎会接受两种密码）。上游版本：MyGo v0.6.2、EasyTier v2.7.0、RustDesk 1.5.0（内置代码）、vcpkg 2026.10.16、
  Rust 1.99.1，已检查，未变。

## 0.5.1 (2026-10-21)

- 远程桌面、VNC 与 SSH：连接被拒绝时不再多打开一个询问 Kyokai 密码的连接标签，主页也不再把服务连接算作设备的桌面连接。
- VNC：在登录过程中关闭连接的服务器（登录失败后的 Mac 屏幕共享）视为登录被拒绝，而不是“无法建立连接”。
- SSH：登录被拒绝或连接被断开时会如实说明；把登录搁置的服务器（登录失败后的 Mac OpenSSH）会说明情况和处理办法；
  服务器拒绝过的密码在同一连接中不会再发送。
- 远程桌面、VNC 与 SSH 第一次连接时会在拨号之前询问登录方式——SSH：密钥或密码；VNC：仅密码、用户名和密码（Mac 的）或无需登录；
  远程桌面：用户名和密码或在远程屏幕上——且不会尝试其他任何方式（不会先试密钥再用密码，也不会用空密码）。打开“记住”后，
  下次连接用同样的方式登录而不再询问，只有失败时才再次询问。
- 电脑的 SSH、远程桌面与 VNC 可以运行在其他端口上：由其用户在“权限”的“本机服务的端口”中设置；其他设备只选择服务，
  到达不了其他端口。主页在这些端口上查找服务。
- 正常结束的隧道不再偶尔被报告为中断（对端刚离开时，这一端最后的回应可能写入失败）。
