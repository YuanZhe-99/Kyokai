# 版本历史

## 0.4.1 (2026-10-21，测试版)

- 切换运行方式时一切都会迁移：此前迁移只带上 0.3.2 之前网络所用的设置名称，所以网络、已保存的密码与访问设置都被留下，
  助手模式看起来像另一台设备。现在整个存储及其文件都会迁移，带有自己设置的另一个身份不会在未经询问时被替换，存储已迁出的引擎
  保持驻留而不生成新身份，Windows 上的助手无需提示即可自行移除。0.4.1 首次启动时会移除此前的切换在未使用的运行方式中遗留的内容。
- 画面从不等待某一条丢失的消息：高延迟下丢掉的关键帧（助手路径在约 230 毫秒时画面冻结，而延迟显示正常）会在每一层再次请求，
  静止的屏幕也会回应，失败的采集或编码器会重新打开，3 秒未确认的帧会被释放，采集会等待空位。熄灭的显示器会被唤醒；查看窗口
  提供“唤醒”，并在恢复画面时告知。助手模式下会话代理跟随输入桌面并保留日志；锁屏与登录屏幕可以显示（采集无论采集到什么都检查
  输入桌面，从不一直复制旧桌面，并从 GDI 取得静止屏幕的第一幅画面）。
- 输入从不卡住：它从不等待卡住的会话，松开总能送达，停顿或重连期间按下的键会被丢弃而不是迟到，会话卡住时键盘抓取让开，
  映射模式让控制端的输入法让开，翻译模式让它完成组字（中文与日文输入曾会让控制端的键盘失去响应）。
- 使用 SSH 式 Ed25519 密钥登录：可连接本机的密钥、你自己的密钥（生成或导入；私钥只显示一次），以及与会话绑定的证明。
- 通过 Kyokai 会话内的隧道连接设备的 SSH、远程桌面与 VNC（包括 Apple 屏幕共享），使用内置客户端（MyGo 的终端；RDP 与 VNC
  来自 open-screen-sharing，GPL-3.0-or-later）；每项都是一个权限，默认关闭；它们的密码与密钥和该设备的 Kyokai 密码保存在一起，
  一并忘记，“安全”中列出保存了什么。Windows 上拒绝本机连接或不提供受支持登录方式的 VNC 服务器会说明
  应更改哪项设置。
- 主页改为设备卡片网格，对保存了密码或密钥的设备静默查看并显示被控端的实时状态：Pulse 风格的图块（大号数值与两分钟的点阵历史），
  涵盖 CPU（应用与系统）、内存、GPU、磁盘（含读写）、网络（含总量）与电池，并为每台设备提供详情页。卡片只在远程桌面、SSH、VNC 与 AI
  无需对方用户即可使用时才提供它们（被控端说明保存的密码授予了什么、其 AI 是否就绪），最常用的排在前面。
- 关闭带有连接的窗口时，若其中有两个及以上连接，或在显示主页时有一个连接，会先询问，并断开它们；关闭主窗口不再让其中的连接继续运行。
- 网络：每个节点都拒绝 EasyTier 的 QUIC 与 KCP 代理入站以及外部网络；“尝试直接连接”移入“高级”并附警告；延迟优先路由。
  各处使用 MyGo 加载插件中的加载指示器。
- 协议 10 并声明功能（`key-login`、`tunnel`、`status`、`input-sync`）：0.4.1 与 0.4.0 以双方共有的能力双向连接（已验证）；
  本地 API 2；ABI 5。
- 上游版本：MyGo v0.6.2（原为 v0.5.5）；EasyTier v2.7.0、RustDesk 1.5.0（引入的代码）、Rust 1.99.1 已检查，未变；vcpkg 2026.10.16（原为 2026.07.29：aom 3.15.2、Opus 1.6.1，libvpx 1.16.0 未变）。

## 0.4.0 (2026-10-19)

- Windows 被控端更快：画面静止不再被当作显示器丢失（以前每次安静片刻都会拆除并重建采集）；重新开始、更换编码或断开后恢复的视频流会重新用上硬件编码器，
  而不是退回软件编码；大分辨率桌面先由 GPU 缩放再复制；退回 GDI 的采集每 2 秒重新尝试桌面复制；指针与人的输入不再占用网络线程。
- Windows：安装了助手时开机启动，Kyokai 不再留下一个空白窗口（它曾运行一个控制台程序来读取助手的版本）。
- Kyokai 的窗口跟随“安全”中的“在屏幕采集中隐藏 Kyokai”：关闭它时（会先询问），控制这台设备的人也可以使用 Kyokai 自己的窗口；
  被控端的 AI 永远不能，有连接请求或 AI 批准在等待时谁都不能。macOS 上，助手模式下 Kyokai 的窗口现在也受到保护。
- macOS：第一次连接请求可能让应用卡住（它在持有锁时通告请求，而 macOS 正在询问通知权限）；看门狗会把卡住的界面的调用栈写入
  `gui-crash.log`。没有“屏幕录制”权限时采集与声音立即放弃，没有 bundle 标识的程序不再让采集过滤器 panic，视频流在释放前先停止，
  系统框架的每个回调都自行捕获 panic。有人连接期间 Mac 被控端保持唤醒。
- 打开日志时，引擎的 stderr、它的 panic 以及每个会话的采集、编码器与声音打开了什么都会写入 `engine.log`。
- 查看窗口的两条栏合并为一条浮在画面上的控制栏，与 RustDesk 一样：“显示器”“画质”“键盘”与“操作”菜单，“声音”“指针”“剪贴板”“AI”
  与“全屏”开关，以及到该设备的路径。拖动其拖动柄可沿顶边移动它（位置对所有查看窗口保留）；它可收起为一个小把手（按设备保存）。
- 协议 10 不变；本地 API 2 新增请求 `input.kyokai`（旧引擎会拒绝它并继续保护 Kyokai 的窗口）。
- 已检查上游版本，均未变化：MyGo v0.5.5、EasyTier v2.7.0、RustDesk 1.5.0（引入的代码）、vcpkg 2026.07.29、Rust 1.99.1。

## 0.3.2 (2026-10-19)

- 同时加入多个网络：“网络”页面最多保存 8 个 EasyTier 网络，每个都有自己的服务器、网络名称、密钥和在此显示的名称，可以同时加入任意多个
  （每个都有“加入”开关），本设备在每个网络中的设备 ID 都相同。按设备 ID 连接时会尝试每个列出该设备的已加入网络，先试直接路径；断开的
  会话会通过仍能到达对方的网络恢复；被控端接受来自所有网络的会话。“尝试直接连接”对所有网络是同一个选择，每个节点在自己的端口上监听。
  早期版本的那一个网络成为第一个网络，保持加入。登录限制按网络分别计算各自的地址（各网络的地址范围会重复）。
- Windows ↔ Mac 测试中发现：Windows 被控端的指针圆环只在拖动时出现（没有接鼠标时 Windows 会隐藏光标，被控端照此报告）；现在被控端像
  Mac 被控端一样报告指针。查看窗口的顶部栏只在 Windows 被控端时出现，因此控制 Mac 时没有“键盘模式”和“交换 Ctrl 与 Cmd”；现在只要会话
  控制被控端就会显示，并且可以像状态栏一样收起（按设备保存）。在 Mac 被控端上，视频流进行中关闭“在屏幕采集中隐藏 Kyokai”可能让 Kyokai
  仍被隐藏：现在视频流会按新设置重新打开；重新启动的会话代理也会收到要共享的声音。
- Windows 的视频路径与 Mac 对齐：编码器把每个画面直接转换进重复使用的 Media Foundation 样本，查看窗口直接在解码后的缓冲区中转换画面
  （除转换本身外，每帧不再有缓冲区或复制），并在 GPU 有 H.264 解码器时用 GPU 解码 H.264，与 Mac 用 VideoToolbox 一样。
- 登录时启动的 Kyokai 不打开窗口，只在托盘中等待（Mac 上它过早询问自己是否为登录项，得到“否”，因此会显示窗口）。
- 协议 10 与本地 API 2 不变：网络功能通过新的请求以及状态中的 `networks` 列表提供，旧请求保留，因此 0.3.2 与 0.3.1 可以互相连接，旧版
  界面也能配合新版引擎使用。
- 已检查上游版本，均未变化：MyGo v0.5.5、EasyTier v2.7.0、RustDesk 1.5.0（引入的代码）、vcpkg 2026.07.29、Rust 1.99.1。

## 0.3.1（2026-10-19）

- 标签栏就是窗口的标题栏：红绿灯（macOS）或最小化、最大化与关闭（Windows）位于其中，旁边是 Kyokai 标签页与各连接的标签页，
  空白部分可拖动窗口（MyGo 的隐藏标题栏），不再是原生标题栏下方再加一行标签页。现在即使没有连接，主窗口也显示标签栏。
- 不再有“设置”页面：侧栏为主页、网络、AI、权限、安全、通用与关于。“尝试直接连接”与“接受地址直接连接”移到网络页面；
  密码、密码授予的权限、受信任设备、共享的声音以及 macOS 的隐私权限移到“权限”；设备身份、保护模式、在屏幕采集中隐藏 Kyokai、
  完全无日志与机密的保存方式移到“安全”；语言、外观、登录时打开、关闭按钮与运行方式移到“通用”；版本、更新、诊断与许可证移到“关于”。
- 查看窗口：“适应窗口”或“原始大小”（按对方电脑每个像素一个点显示，比窗口大时可双向滚动），按设备保存；“剪贴板”面板，带一个
  是否与该设备共享剪贴板的开关（按设备保存），以及其标签页位于前台期间经过的内容，来自该设备或来自本机，只在内存中保留到关闭标签页。
  有多个连接时，只有位于前台的标签页交换剪贴板；标签页在后台时复制的内容会在它回到前台时发送。
- 协议 10，未变：剪贴板选择只在界面与其引擎之间传递（本地 API 2，只有新增），因此 0.3.1 与 0.3.0 可以互相连接。
- 已检查上游版本，均未变化：MyGo v0.5.5、EasyTier v2.7.0、RustDesk 1.5.0（引入的代码）、vcpkg 2026.07.29、Rust 1.99.1。

## 0.3.0（2026-10-18）

- 按地址连接：“控制另一台设备”除设备 ID 外也接受 IP 地址或域名，经普通 TCP 连接，无需网络；被控端只有在打开“接受地址直接连接”
  （设置、访问；默认关闭）时才接受，并且只接受来自所列地址网段的连接（默认为局域网和 Tailscale 的 100.64.0.0/10）。“最近”会记住该地址。
  网络页面中经由地址连接 EasyTier 节点的直连地址已删除。
- 最近：“移除”现在会真正移除设备（之前它已结束的连接会让它再次出现），“重命名…”为设备起一个只在本机显示的名称。
- 查看窗口：窗口较窄时各栏换成多行（之前控件会超出边缘），状态行可以完全收起（⌄），只留一个小 ⌃ 标签用来重新拉出，按设备保存。
- 完全无日志（设置、存储；默认关闭，警告后打开）：不写日志或崩溃跟踪并删除已写下的，受信任设备与“最近”只保存在内存中。
- 保护模式（设置、访问；需要固定密码）：Kyokai 只提供 AI 设置和 AI 任务，引擎拒绝其他一切，只有固定密码能关闭它。
- 协议 10，未变：0.3.0 与 0.2.0 可以互相连接；0.2.0 的被控端不接受地址直接连接。
- 已检查上游版本，均未变化：MyGo v0.5.5、EasyTier v2.7.0、RustDesk 1.5.0（引入的代码）、vcpkg 2026.07.29、Rust 1.99.1。

## 0.2.0（2026-10-18）

- 查看窗口：对方电脑的指针跟随鼠标（之前没有按住按键的移动被丢弃，所以指针只在点击时移动），每秒报告 60 次；“编码”选择（“自动”
  以及两台电脑都支持的编码）；直连或中继；以及数字上的提示，说明时间花在哪里（被控端的编码、网络、本机的解码与绘制）。
- macOS：经 VideoToolbox 以硬件编解码 H.264 与 HEVC，在 Mac 被控端与 Mac 查看窗口中都是如此，因此有 Mac 参与的会话不再退回到软件 VP9；
  “在屏幕采集中隐藏 Kyokai”现在即时决定 Kyokai 自己的采集与 AI 截图能看到什么。
- 网络：打开“尝试直接连接”时，节点会监听（TCP 与 UDP，端口 47311–47320），因此同一网络中的设备直接相连，而不再经由服务器中转；
  关闭时，任何方向都不建立直接连接。
- 更低的延迟：像素转换快四到五倍；只在会话能发送时才取画面；落后的查看窗口从下一个关键帧继续，而不是解码损坏的画面；解码不再等待
  绘制；查看窗口打开时不再丢失视频流的第一幅画面。点击与按键绝不会因指针移动而被丢弃。
- 测试版中发现的问题：较旧的助手由应用自行更新，签名版本不弹出提示（应用更新会把它落下，使它所在的设备连不上已更新的设备），版本不一致时会说明哪一端不同；被控端最多领先查看窗口的确认 3 帧（在慢速中继上，数秒的视频曾堆积在传输中，9.9 秒、1 fps）；关闭直接连接的设备仍会连接正在监听的局域网对端，该开关移到“设置”的“运行方式”中，切换后立即生效；网络页面的设备显示名称，并有“复制”与“连接”；从 Mac 的查看窗口输入的按键能到达被控端（macOS 之前没有给画面文字）；“编码”选择只显示编码名称，查看窗口的详情说明用什么编码与解码、是硬件还是软件；Mac 被控端优先请求硬件编码器。随后：同一版本但构建不同的助手也会更新；各个方向的键盘：快捷键的修饰键不再一直按在被控端上，Mac 查看窗口会抓取键盘（映射与翻译，需要“辅助功能”），在传统模式下把菜单的拷贝、粘贴等作为 Cmd 快捷键发送，Mac 与 Windows 之间默认打开“交换 Ctrl 与 Cmd”；每台设备的查看设置都会记住。Mac 的键盘抓取不再让其他程序的键盘失灵。声音：查看窗口播放对方电脑正在播放的声音（Opus 1.5.2、ScreenCaptureKit 与 WASAPI 回环），并带有“声音”开关；10 毫秒的低延迟数据包，被控端静音时不发送，40–400 毫秒、先攒够目标再播放的抖动缓冲，单独的“听到声音”权限（默认打开），以及在设置中选择共享的声音（本机播放的声音，或麦克风等输入）。
- 下一轮测试中发现：会话在每条消息之后都 flush，而 EasyTier 的 flush 会等待对端确认，因此视频、声音和输入加起来每个往返只能传一条
  消息（帧率上不去，声音卡顿，一阵声音甚至会让会话卡住）：写入不再 flush，在这台 Mac 上帧率从 0–13.5 提升到 26.6 fps，声音的
  间隔最多 32 毫秒。查看窗口像 RustDesk 的客户端一样，在不同的 goroutine 中读取、解码视频与播放声音。有人输入后的 2 秒内，只要
  延迟较低，被控端就按查看者的帧率上限发送（RustDesk 的 QoS 只靠探测从 15 慢慢提升）。Kyokai 退出的设备会发送告别，另一端立即结束
  会话，而不是一分钟之后。网络页面新增直连地址（其他设备的 IP 地址或域名，无需服务器的网络）与“清除网络设置”。
- 线路协议 10（0.2.0 的设备只与 0.2.0 相连）、FFI ABI 5、本地 API 2。
- 检查（2026-10-18）：MyGo v0.5.5、EasyTier v2.7.0（提交 `8b7f1f0`）、RustDesk 1.5.0、vcpkg 2026.07.29 与 Rust 1.99.1
  均为最新；已检查，未变化。

## 0.1.1（2026-10-17）

macOS 版本（Apple 芯片、Intel），并参照 RustDesk 重做了连接。

- macOS：ScreenCaptureKit 采集、带键盘模式的 CGEvent 输入、隐私权限（屏幕录制、辅助功能、输入监控、钥匙串）的请求及其在主页上的显示；
  通过 LaunchDaemon 助手与 LaunchAgent（Kyokai Helper）提供运行方式，安装时只需一次管理员提示，按代码签名更新，移除时无需提示；
  使用 Apple Development 证书签名，授权与钥匙串访问可跨更新保留。
- 连接：只有设备，界面中没有会话。主页显示本机、控制另一台设备与最近设备的卡片（菜单：连接、连接并使用 AI、忘记密码、移除）。
  每个连接是主页旁的一个标签页，可拖出成为单独的窗口再拖回，支持全屏；询问被控端期间可输入密码并记住密码，结束后可重新连接。
- 访问：接受的密码（临时密码、固定密码或两者）与全局的无需确认即可连接（默认开启）取代了按设备的无人值守授权；无人在电脑前时只有固定密码可以进入。
- AI：被控端为所有控制端保留同一份 AI 记录，下一条指令的草稿在被控端与每个控制端之间实时共享。线路协议 6、FFI ABI 4、本地 API 2。
