# 版本历史

## 0.1.3（2026-10-18）

- 查看窗口：对方电脑的指针跟随鼠标（之前没有按住按键的移动被丢弃，所以指针只在点击时移动），每秒报告 60 次；“编码”选择（“自动”
  以及两台电脑都支持的编码）；直连或中继；以及数字上的提示，说明时间花在哪里（被控端的编码、网络、本机的解码与绘制）。
- macOS：经 VideoToolbox 以硬件编解码 H.264 与 HEVC，在 Mac 被控端与 Mac 查看窗口中都是如此，因此有 Mac 参与的会话不再退回到软件 VP9；
  “在屏幕采集中隐藏 Kyokai”现在即时决定 Kyokai 自己的采集与 AI 截图能看到什么。
- 网络：打开“尝试直接连接”时，节点会监听（TCP 与 UDP，端口 47311–47320），因此同一网络中的设备直接相连，而不再经由服务器中转；
  关闭时，任何方向都不建立直接连接。
- 更低的延迟：像素转换快四到五倍；只在会话能发送时才取画面；落后的查看窗口从下一个关键帧继续，而不是解码损坏的画面；解码不再等待
  绘制；查看窗口打开时不再丢失视频流的第一幅画面。点击与按键绝不会因指针移动而被丢弃。
- 测试版中发现的问题：较旧的助手由应用自行更新，签名版本不弹出提示（应用更新会把它落下，使它所在的设备连不上已更新的设备），版本不一致时会说明哪一端不同；被控端最多领先查看窗口的确认 3 帧（在慢速中继上，数秒的视频曾堆积在传输中，9.9 秒、1 fps）；关闭直接连接的设备仍会连接正在监听的局域网对端，该开关移到“设置”的“运行方式”中，切换后立即生效；网络页面的设备显示名称，并有“复制”与“连接”；从 Mac 的查看窗口输入的按键能到达被控端（macOS 之前没有给画面文字）；“编码”选择只显示编码名称，查看窗口的详情说明用什么编码与解码、是硬件还是软件；Mac 被控端优先请求硬件编码器。
- 线路协议 8（0.1.3 的设备只与 0.1.3 相连）、FFI ABI 5、本地 API 2。
- 检查（2026-10-18）：MyGo v0.5.5、EasyTier v2.7.0（提交 `8b7f1f0`）、RustDesk 1.5.0、vcpkg 2026.07.29 与 Rust 1.99.1
  均为最新；已检查，未变化。

## 0.1.1（2026-10-17）

macOS 版本（Apple 芯片、Intel），并参照 RustDesk 重做了连接。

- macOS：ScreenCaptureKit 采集、带键盘模式的 CGEvent 输入、隐私权限（屏幕录制、辅助功能、输入监控、钥匙串）的请求及其在主页上的显示；
  通过 LaunchDaemon 助手与 LaunchAgent（Kyokai Helper）提供运行方式，安装时只需一次管理员提示，按代码签名更新，移除时无需提示；
  使用 Apple Development 证书签名，授权与钥匙串访问可跨更新保留。
- 连接：只有设备，界面中没有会话。主页显示本机、控制另一台设备与最近设备的卡片（菜单：连接、连接并使用 AI、忘记密码、移除）。
  每个连接是主页旁的一个标签页，可拖出成为单独的窗口再拖回，支持全屏；询问被控端期间可输入密码并记住密码，结束后可重新连接。
- 访问：接受的密码（临时密码、固定密码或两者）与全局的无需确认即可连接（默认开启）取代了按设备的无人值守授权；无人在电脑前时只有固定密码可以进入。
- AI：被控端为所有控制端保留同一份 AI 记录，下一条指令的草稿在被控端与每个控制端之间实时共享。线路协议 6、FFI ABI 4、本地 API 2。
- 修复：停止中的引擎不再删除后继引擎的套接字；注销时可以正常退出；“重新打开”不再启动第二个副本；无法解锁的存储提供“重新开始”；
  崩溃跟踪写入日志文件夹。
- 发布检查（2026-10-17）：MyGo v0.5.5、EasyTier v2.7.0（提交 `8b7f1f0`）、RustDesk 1.5.0、vcpkg 2026.07.29 与 Rust 1.99.1
  均为最新；已检查，未变化。

## 0.1.0（2026-10-17）

首个发布版本，适用于 Windows（x64、ARM64）；macOS 随后提供。

- 连接：内嵌的 EasyTier 节点经标准服务器连接（未打开直接路径时经中继）、设备 ID 解析、带 OPAQUE 登录的 Noise XX（临时与固定密码）、
  被控端确认、受信任设备、无人值守授权、限速、会话恢复、身份备份、带厂商标志的友好名称。线路协议 4、FFI ABI 3、本地 API 2。
- 手动 Computer Use：DXGI 采集与 GDI 回退、多显示器、Media Foundation H.264 / HEVC / VP9（有硬件时使用硬件）、libvpx VP8 / VP9
  与 libaom AV1、全彩 4:4:4、RustDesk 的 QoS 与画质预设、带 RustDesk 键盘模式的输入、远程指针、剪贴板文本、图片与文件、
  会话操作（锁定、Ctrl+Alt+Del、输入阻止、隐私模式）。
- 在被控端用其自己的密钥运行的 AI Computer Use：从模板添加的 Claude、OpenAI 与 OpenAI 兼容服务商、批准、接管、紧急停止、
  睡眠时暂停、由控制端操控的任务。
- 运行方式：免授权、跟随 Kyokai 与后台服务，经由签名、可自我更新、可自行停用的特权助手及位于输入桌面的会话代理。

- 仓库脚手架：工作规范（`AGENTS.md`）、镜像文档、上游版本检查、Rust 工作区与 Go 模块；生成发布签名材料
  （应用更新、特权助手 bundle、macOS 代码签名）。
- 基础：Rust 核心（系统凭据存储保护的机密存储、持久的设备身份与设备 ID、临时密码）及带版本的 C ABI；作为界面用户级
  子进程运行并提供本地 API 的 `kyokai-svc` 引擎；界面（主页、设置、托盘、四种语言、签名的应用更新）；CI 与发布工作流；
  Windows 安装包。
- Phase 0：S1 EasyTier、S2 画面与 S3-lite 采集可行性验证在 Windows ARM64 上通过。
- MyGo v0.5.5 / Rust 1.99.1；为后续阶段固定 EasyTier v2.7.0（预发布版，提交 `8b7f1f0`）与 RustDesk 1.5.0
  （提交 `fada664`）（2026-10-16 检查）。
- 为软件编解码器固定 vcpkg 2026.07.29（提交 `9e593bb`：libvpx 1.16.0、aom 3.13.3）；MyGo v0.5.5、EasyTier v2.7.0、
  RustDesk 1.5.0 与 Rust 1.99.1 未变（2026-10-17 检查）。
- 发布检查（2026-10-17）：MyGo v0.5.5、EasyTier v2.7.0（提交 `8b7f1f0`）、RustDesk 1.5.0、vcpkg 2026.07.29 与 Rust 1.99.1
  均为最新；已检查，未变。
