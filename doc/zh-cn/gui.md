# 界面

界面面向使用 Kyokai 的人，而不是工程控制台（`internal/gui`）。`internal/gui/gui_test.go` 以每种语言和主题渲染每个页面，
设置 `SCREENSHOT_DIR` 时写出截图。

## 结构

- **主窗口：** 标签栏就是窗口的标题栏（MyGo 的隐藏标题栏，`TitleBarOptions`）：窗口自己的控制按钮位于其中——macOS 上的红绿灯，Windows 上的最小化、最大化与关闭，与标签栏同高——然后是 Kyokai 标签页（主页）以及每台已连接的设备一个标签页（[连接](#连接)）；标签栏的空白部分可拖动窗口，双击它会像标题栏一样缩放或最大化窗口。全屏时标签栏隐藏。
- **侧栏：** Kyokai 的标志与名称，然后是主页、网络、AI、权限、安全、通用与关于，各带图标（`internal/gui/assets/icons` 中的原创线条图），左对齐。不再有单独的“设置”页面：除主页外的每个页面都是一类设置。
- **主页**，布局与 RustDesk 相同：左侧“本机”——按三位一组显示的设备 ID 及“复制”；临时密码，在点“显示”前遮蔽，可“复制”和“换一个密码”（只接受固定密码时，改为一行说明，未设置固定密码时为一条警告）；机密未持久化时显示提示；已保存的身份无法解锁时提供“重新开始”（旧存储移到一旁，此后保存一个新身份；`secrets.start_over`）。右侧“控制另一台设备”：设备 ID 或地址（IP 地址或域名，用于接受地址直接连接的设备；询问对方是谁期间显示“正在查找该地址上的设备…”）、“选项”（同时请求在对方电脑上运行 AI 任务）与“连接”（按设备 ID 连接需要先加入网络）。在 macOS 上，缺少“屏幕录制”、“辅助功能”、“输入监控”或钥匙串时显示“隐私权限”，每项带“允许”（“权限”页中始终显示）；本次运行中请求过的权限还提供“重新打开 Kyokai”，因为 macOS 只在授权之后启动的引擎中计入新授权。在助手模式下，卡片说明这些是 Kyokai Helper 的权限，缺少的一项提供“重启 Kyokai Helper”。主页比其他页面更宽（`homeMaxW`，1120）。下方是**最近**：设备卡片的网格——每台设备一张，绝不是每个会话一张——每张至少 300 宽，每行一到三张（`homeColumnsFor`）。卡片包括：标题行（头像、名称——本机为它起的名称，否则为它的别名——与设备 ID、以标签显示的状态：已连接、正在连接、在线或离线，以及 ⋯）；网络如何到达它（一个圆点与“直连 · 12 ms”、以警告色显示的“中继 · 231 ms”、“按地址”、上次尝试失败的原因，或最近连接时间）；它的实时状态；为它保存了什么的标签（Kyokai 密码、密钥、SSH、远程桌面、VNC；只有标记）；以及操作：“连接”（已连接或正在连接时为“显示”），然后是状态报告正在监听的服务对应的 SSH、远程桌面与 VNC（对方没有 Kyokai 0.4.1 的隧道时禁用并带提示），以及 AI（连接并使用 AI）。⋯ 菜单中有“连接”、“连接并使用 AI”、“打开 SSH / 远程桌面 / VNC”、“重命名…”（只在本机显示的名称，在设备上方的卡片中编辑；留空则恢复设备自己的别名）、“已保存的密码与密钥…”（安全页面）、“忘记旧身份”（密钥变化后）与“移除”（断开连接，把它及其已结束的连接移出“最近”，并忘记其固定的密钥、保存的登录信息与本机为它起的名称）。
- **主页上的实时状态：** 主页显示期间（主窗口可见，位于其 Kyokai 标签页与主页），界面为最近的设备租用一次查看（`watch.set`，最多八台，每 10 秒续租，主页隐藏时撤回）。被查看设备的卡片以两列图块显示：CPU（一条仪表，80 % 起为警告，95 % 起为严重，以及最近 60 个样本的走势线）、内存与磁盘（已用 / 总量）、GPU（被控端没有可报告的则隐藏）、网络（↓ 与 ↑，并有收到数据的走势线）、电池（20 % 起为警告，10 % 起为严重；没有电池则隐藏）与运行时间。绝不把过时数据当作当前数据：6 秒以内的样本照常显示；6 到 60 秒之间图块变暗并显示“N 秒前更新”；更旧则不显示数值，只显示“HH:MM 时的状态”，走势线清空。没有样本时卡片说明查看的进展：带加载指示器的“正在获取状态…”、没有保存的密码或密钥、需要对方安装 Kyokai 0.4.1，或被拒绝。
- **确认：** 等待被控端用户确认的控制端显示在每个页面顶部，包括其设备 ID、是否已知或是冒用已知 ID 的新密钥、未使用密码时的警告，以及每个所请求
  权限的开关，并提供“允许”（主按钮）与“拒绝”；在 macOS 上，若所请求的功能缺少“屏幕录制”或“辅助功能”则给出警告；同时发出通知并把窗口带到前面。
- **已连接到本机：** 另一台设备连接到本机（或正在恢复）时，每个页面顶部有一张卡片写明是哪台设备、它可以做什么，并提供“断开”。
- **AI：** 任务卡片——新任务的指令与“开始”（服务商没有密钥时给出提示；正在编写的指令与每个已连接控制端的 AI 面板实时共享），或进行中的任务：以文字说明其状态（正在操作、
  等待批准、已暂停及原因、已完成、已停止），模型最新的文字与进度说明，以文字描述的最近几个操作（“在 640, 425 处单击”、
  “按 Ctrl+S”）及其结果，以及“暂停”或“继续”和“停止”；等待批准的操作显示在带边框的框中，附“允许”“拒绝”与服务商的说明。
  已完成的任务可以通过回复继续。下方是服务商卡片——任务使用的模型（所有来源的所有模型，以 `厂商: 模型` 名称列出）、批准方式、各来源及其模板、模型数与密钥状态（编辑、移除），
  以及从模板“添加服务商”；编辑器包括名称、地址（模板的各站点按名称列出）、自定义时的格式、只写的密钥、带“移除”的模型列表、要添加的 id 与“列出模型”（已保存的来源）
  以及带“清除历史”的任务历史。任务等待批准期间，其他每个页面都会显示带“查看”的横幅，并发出通知。控制端的任务会显示“由”其设备 ID“发起”，
  它工作期间，其他每个页面都会显示带“查看”与“停止”的横幅。
- **网络：** 保存的网络（最多 8 个），并说明本设备在每个网络中的设备 ID 都相同。每个网络显示它在此显示的名称（或网络名称）及其下方的
  网络名称、“加入”开关（立即生效；被拒绝时显示引擎给出的原因，随后页面重新读取网络）、“编辑”与“移除”（确认后 Kyokai 离开该网络，并忘记
  它的服务器、名称和密钥）、它的实时状态（已连接、正在连接、无法连接及原因，或未加入；虚拟地址；用通俗说法描述的 NAT 类型；监听时直接连接
  的端口）以及它能路由到的 Kyokai 设备（设备上次在本机会话中给出的名称（若有）、设备 ID、直连或中继、延迟、“复制”与“连接”）。
  “添加网络”和“编辑”在原处打开同一个表单：在此显示的名称（可选）、服务器（每行一个 URL）、网络名称和只写的密钥字段（留空保留已存的密钥；
  弱密钥会被标出），以及“保存”（有服务器和名称时才可用）与“取消”；被拒绝的设置会显示引擎给出的原因。提示说明设备宣告的 ID 不能作为证明。最后是其他设备如何连接本机：“尝试直接连接”（默认关闭；助手模式下固定打开；切换后立即生效，[networking.md](networking.md)）与“接受地址直接连接”，默认关闭，打开时显示接受的网段，每行一个，带“保存”与“取消”，无法监听时给出警告。
- **设备名称：** 设备出现的每个地方（确认请求、最近设备、连接标签页、受信任设备、查看窗口标题、网络页面）都会在设备 ID 旁显示它的名称——本机用户为它起的名称（`gui.json` 的 `aliases`，从不发送到任何地方），否则为它自己的别名——而不是代替设备 ID，
  并带有圆形头像（`deviceAvatar`）：设备的厂商、型号、别名或系统（按此顺序尝试；只匹配完整单词，因此 `hp` 不会匹配 `php-dev`）
  指明某个已知厂商或系统时（`deviceLogoName`）显示该厂商的单色标志，否则显示别名的首字母。厂商标志是其所有者的商标，只用于表明设备的厂商；
  来源列在 `internal/gui/assets/logos/SOURCES.md` 中（见 [packaging.md](packaging.md) 的“厂商标志”）。
- **权限：** macOS 上首先是“隐私权限”；密码（固定密码：设置、更改或移除；“接受的密码”：临时密码、固定密码或两者；“无需确认即可连接”，默认开启，其下为“使用正确密码时”：密码无需确认即可授予的每个权限一个开关，其中“查看本机状态”默认开启，“连接其 SSH”、“连接其远程桌面”与“连接其 VNC 或屏幕共享”默认关闭）；正在查看本机状态的设备及其开始时间；受信任设备及其最近连接时间与“移除”；共享的声音——未选择输入设备时为本机正在播放的声音，已不在的设备显示为当前未连接，选择输入时向 macOS 请求“麦克风”权限。
- **安全：** 设备身份（设备 ID、别名、指纹；通过文件对话框以口令备份和恢复；在警告后重置）；密钥，这是唯一显示密钥及其指纹的页面：“你的密钥”（名称、类型与 `SHA256:` 指纹、“复制公钥”、确认后“移除”；“生成密钥”——Ed25519，私钥以 OpenSSH 格式只显示一次，带“复制”与“保存到文件…”，用给出的口令加密，之后由引擎保存；“导入密钥”——粘贴或来自文件，OpenSSH 或 PEM，加密的密钥会要求口令；支持 Ed25519、2048 位及以上的 RSA、ECDSA P-256 或 P-384），“可连接本设备的密钥”（同样的行；“添加密钥”接受一行 OpenSSH 公钥或 `.pub` 文件，以其注释命名；“生成密钥对”——公钥可连接本机，私钥只显示一次，绝不保存）与“已保存的密码与密钥”（每台保存了内容的设备：每项登录信息一个标签，带 × 可忘记，以及“全部忘记”）；“保护模式”（仅在设置了固定密码时可用，需确认）；隐私：在屏幕采集中隐藏 Kyokai——默认打开，立即作用于主窗口和每个查看窗口并告知引擎，macOS 上引擎的采集随之改变；关闭后（先警告），控制这台设备的人的输入也能到达 Kyokai 的窗口，AI 的永远不能，有请求或批准在等待时任何人的都不能——机密的保存方式，以及“完全无日志”——默认关闭，打开前警告此后无人能知道谁连接过、本机连接过谁，正在使用的引擎尚不支持时给出提示。
- **通用：** 语言、外观、登录时打开——默认关闭；登录时启动的 Kyokai 不显示窗口，只显示托盘图标（Mac 上作为登录项，在应用就绪后才询问：更早询问时 macOS 回答“否”）——与关闭按钮；运行方式：免授权 / 随界面 / 后台服务，并说明那一次管理员提示以及哪些内容会随之迁移；切换在后台进行，完成后以提示告知（[run-modes.md](run-modes.md)；Windows 与 macOS）。
- **关于：** 版本、许可证、源代码与应用更新；诊断（版本与 ABI、引擎启动时间、运行方式、数据文件夹及“打开文件夹”、日志文件夹，完全无日志时显示“已关闭”）；开源许可证（随附的声明）。
- **保护模式：** 侧栏只显示 AI，每个页面都是 AI 页面，顶部是带固定密码输入框与“关闭”的卡片（密码错误时会提示）；确认请求与已连接到本机的设备仍会显示。
- 引擎会话连接之前，需要它的页面显示“正在启动…”或引擎未运行的原因。
- **应用更新（关于）：** 每日检查（可关闭）与“检查更新”读取 GitHub 最新发布的已签名更新；“安装并重启”会先停止引擎，
  就地安装后重新启动。开发版本会说明无法自行更新。

## 连接

- 每台设备一个连接，从一开始就显示为一个标签页，与 RustDesk 相同。连接会在主窗口中打开标签页：“正在连接…”；询问设备的用户时显示“等待对方设备允许…”，并附“或输入对方的密码”、“记住密码”与“连接”（等待中的请求会被放弃，因此设备同时只有一个请求）；然后是画面。连接结束或失败时，标签页说明原因（包括密码错误），并附密码栏与“重新连接”。密码留空时使用为该设备保存的密码，否则询问其用户。关闭标签页（×）即断开连接。把标签页拖到另一个 Kyokai 窗口的标签行上即移到那里；拖到 Kyokai 之外放开，或点它的 ⧉，就得到一个单独的窗口，最后一个标签页关闭时该窗口随之关闭；关闭这样的窗口会断开其中的标签页。为窗口抓取的按键送到显示中的标签页。标签页可以是一台设备的桌面，也可以是它的某项服务（SSH、远程桌面、VNC；`tab`、`serviceTab`），每台设备每种一个，每种都同样可以拖动、移动与关闭。
- 服务标签页（[remote-services.md](remote-services.md)，“客户端”）的标题如“SSH · 设备”。它先显示带加载指示器的“正在连接SSH…”，已保存的内容都不可用时显示登录表单（用户名；远程桌面另有域；VNC 的用户名只有 Mac 需要；密码；记住密码；“取消”与“登录”），然后是客户端：SSH 为 MyGo 的终端，采用应用的浅色或深色主题；远程桌面与 VNC 为对方桌面的画面，控制栏有“显示”（适应窗口或原始大小）、“键盘”（键盘模式）、“操作”（Ctrl+Alt+Del）与“全屏”。结束时说明原因并提供“重新连接”；SSH 服务器的密钥变化后还提供“信任新密钥”。
- 画面在黑色背景上按比例显示，或选择“原始大小”时按被控端每个像素一个点显示，比窗口大时可双向滚动（拖动滚动条移动；会话控制被控端时滚轮发送到被控端），比窗口小时居中；用一个跟随鼠标的小圆环标出被控端的指针。与 RustDesk 一样，一条控制栏浮在画面顶边上：拖动它的拖动柄（或控制之间的空隙）可沿顶边移动它，松开的位置对所有查看窗口记住（`gui.json` 中的 `toolbar_at`）；⌃ 把它收起为同一位置上的一个小把手（拖动柄与 ⌄），按设备保存。它的图标各由提示说明名称：“显示器”（被控端有多个显示器时按编号选择；“适应窗口”或“原始大小”）、“画质”（预设、“帧率”下的上限如“30 fps”、有可选项时“编码”下的“自动”以及两台电脑都支持的编码（只显示编码名称），以及“全彩”）、“键盘”（拥有 `control-input` 时，在 Windows 与 macOS 上：键盘模式映射、翻译或传统，对所有查看窗口记住；任一端是 Mac 时还有“交换 Ctrl 与 Cmd”；Mac 上没有 Kyokai 的“辅助功能”权限时图标显示为警告色，其提示说明要允许它）、“操作”（拥有 `control-input` 且被控端提供时，即 Windows 被控端：锁定屏幕、助手模式下的 Ctrl+Alt+Del、“阻止对方的键盘和鼠标”与“隐私模式”，按被控端报告的状态勾选），然后是“声音”（播放被控端的声音；未选择时打开，按设备保存）、“指针”（显示或隐藏圆环，对所有查看窗口记住）、“剪贴板”（拉出剪贴板面板，拥有 `clipboard` 或 `files` 时）、“AI”（收起 AI 面板）与“全屏”这几个开关；窗口较窄放不下的进入控制栏的 » 菜单。它们旁边是路径：一个圆点与直连或中继（中继显示为警告色，其提示建议在两台设备上都打开直接连接）以及被控端测得的延迟，提示中还有尺寸、编解码器、帧率与码率，用什么编码、用什么解码（各自按其报告为硬件或软件），以及时间花在哪里（被控端的编码、网络、本机的解码与绘制、帧率与被控端目标帧率的对比）——对于不能录制屏幕的被控端发来的测试图案，则是一个警告标志，说明“这是占位画面”。在控制栏中做出选择后，画面重新接收键盘；画面上的鼠标、滚轮与键盘操作会发送到被控端（[computer-use.md](computer-use.md)），在控制栏上按下则永远不会。画质预设、帧率上限、“适应窗口”或“原始大小”、“全彩”、“编码”、“交换 Ctrl 与 Cmd”、剪贴板开关以及控制栏是否收起按设备保存（`gui.json` 中的 `viewers`）：设备的查看窗口以上次为它选择的设置打开。
- 剪贴板面板：“与这台设备共享剪贴板”（除非关闭，否则打开，按设备保存），以及该设备的标签页位于前台期间经过剪贴板的内容，最新的在前（最多 30 条，只在内存中，关闭标签页即消失）：每条的来源——来自该设备（被控端）或来自本机（控制端）——与时间，然后是文本及“复制”、图片的缩略图及其尺寸，或文件的名称、数量与大小；“清除”清空列表。只有位于前台的标签页——在最近使用的 Kyokai 窗口中显示的那个；该窗口显示 Kyokai 标签页时则没有——交换剪贴板（[computer-use.md](computer-use.md)，“剪贴板”）；标签页不在前台时面板会说明。两个面板可以同时显示，剪贴板面板在 AI 面板左侧。
- 拥有 `run-ai-task` 时，标签页有 AI 面板“对方电脑上的 AI”，可用“AI”开关收起（有步骤等待批准时仍会显示）。它显示被控端唯一的一份 AI 记录，无论任务由谁发起，每个控制端看到的都相同（状态、模型的文字、最近的操作、“暂停”或“继续”和“停止”、完成后的回复），以及正在编写的指令，它与被控端的 AI 页面和其他每个控制端实时共享（在此处输入后的一秒内，不会被别处输入的草稿覆盖）。拥有 `approve-ai-action` 时批准请求带“允许”“拒绝”，否则提示由被控端用户批准。连接会请求查看、输入、剪贴板与文件；使用“连接并使用 AI”（或该选项）时还会请求 `run-ai-task` 与 `approve-ai-action`。

## 措辞规则

- 文案写给使用应用的人。
- 从不显示：原因代码、密钥、套接字路径、除设备 ID 以外的内部标识（指纹、登录密钥及其指纹只出现在安全页面上；
  已保存的登录信息只显示为标记，绝不显示其密码）。

## 视觉语言

- MyGo 浅色/深色主题加系统强调色；布局数字是 `style.go` 中的命名常量。
- 正文 14，标题 20–24，不小于 12；设备 ID 为 34，使用等宽数字。
- 正在进行的事情都显示同一个加载指示器：MyGo 加载插件中 loading-dev 的 Arc，使用强调色（在查看器的黑色背景上为
  白色），并以正在加载的内容为辅助技术命名。
- 应用图标为原创作品：一个被边界线（鏡界）分开的圆环，一侧实心、一侧描边，一个指针跨过边界。托盘以单色模板图形
  显示同一标志：白色；Windows 以浅色绘制任务栏时（`SystemUsesLightTheme`，每次状态更新时检查）改用黑色（`tray-black.png`）；macOS 自行为模板着色。
  `go run ./tools/icon resources/icon.png internal/gui/assets/tray.png` 按其几何形状绘制全部图形。

## 托盘

- 菜单：设备 ID（不可点）、有任务进行时的“停止 AI 任务”（紧急停止）、显示 Kyokai、退出 Kyokai。从不显示密码。
- Kyokai 的窗口不参与屏幕采集，因此查看窗口和 AI 任务都看不到它们，远程输入也到达不了它们，除非关闭了“安全”中的“在屏幕采集中隐藏 Kyokai”（AI 永远到达不了）。
- 关闭窗口时隐藏到托盘，并在第一次时说明；没有托盘，或关闭按钮选择“退出”时，关闭即退出。退出应用本身（应用菜单、程序坞、注销或关机）总会退出，从不询问，并让引擎结束本界面的连接（`sessions.close_controllers`，最多等一秒）。
- 关闭窗口时由 `decideClose` 决定：关闭按钮选择“退出”时，关闭主窗口会在任何地方有活动连接时询问，然后退出；否则，窗口中有两个或以上活动连接（正在连接、等待中、已连接或正在重连；桌面与服务一样），或有一个看不到的连接（主窗口显示主页）时询问，然后断开其中的标签页并隐藏（主窗口）或关闭。询问是一个列出这些连接的对话框，带“断开并关闭”（或“断开并退出”）与“取消”。
- 在 macOS 上，只有打开着 Kyokai 窗口（主窗口或连接的单独窗口）时程序坞中才显示图标；只剩菜单栏图标时，Kyokai 会离开程序坞与应用切换器，打开窗口后图标随之回来。

## 语言

通过 MyGo 的 ARB 目录支持英文、简体中文、繁体中文与日文（`go tool mygo i18n check`）。应用跟随系统语言，也可手动切换。
