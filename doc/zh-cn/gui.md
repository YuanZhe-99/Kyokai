# 界面

界面面向使用 Kyokai 的人，而不是工程控制台（`internal/gui`）。`internal/gui/gui_test.go` 以每种语言和主题渲染每个页面，
设置 `SCREENSHOT_DIR` 时写出截图。

## 窗口

- **主窗口**由窗口底色上的侧边栏——Windows 11 上为 Mica，macOS 上为侧边栏材质，其他系统为主题的背景色——与旁边的小窗组成：圆角的框（14 点圆角，带边框与淡淡的阴影），与窗口边缘、彼此之间都相距 8 点浮动（`shellView`）。主页、每台设备的桌面以及它的每项服务（SSH、远程桌面、VNC）、被控端的状态与每个 AI 会话各是一个小窗（`tab`：`homeTab`、`viewer`、`serviceTab`、`statusTab`、`aiTab`）。等待用户处理的请求、连接到本机的设备以及本机的 AI 任务以卡片显示在小窗上方——每张卡片本身也是一个与小窗对齐的框（`noticeCard`），需要用户决定的（连接请求、等待批准的 AI 任务）以强调色着色，有人正在本机工作的（连接到本机的设备、控制端的 AI 任务）以警告色着色——提示消息显示在它们底部。窗口以焦点所在的小窗命名，AI 会话的标题或设备名称变化时也会重新命名。
- **侧边栏**（`sidebarView`）：顶部是“隐藏侧边栏”与 +（+ 选择器，见下文），macOS 上位于红绿灯之后；带 Kyokai 标志的主页；“已打开”及打开的小窗数量，然后按打开的顺序每个分组一个条目——单独的小窗为一行（类型图标、设备名称、以文字写出的类型：桌面、SSH、远程桌面、VNC），多个小窗的分组为一张卡片，上方是各设备的名称（“Studio Mac + NUC”），下方是各小窗的行——最后是独立窗口中的小窗，点按会把窗口带到前面。正在显示的条目突出显示，分组中焦点所在的小窗以强调色的浅色标出；拖动一行与拖动其标题栏一样拖动小窗。底部：搜索（见下文）、外观（依次为跟随系统、浅色与深色——半填充的显示器、太阳、月亮）、齿轮（设置），以及以圆点和文字（在线、正在连接…、无法连接、离线；引擎应答之前为“正在启动…”或“引擎未运行”）显示的网络状态，点按打开设置中的网络。隐藏后，侧边栏变为一列图标，分组的图标带数量，名称在提示中（`gui.json` 中的 `sidebar_rail`）。
- **小窗的标题栏**（44 点）：类型图标、设备名称（最多 200 点）及其设备 ID（或服务，或 AI 会话的标题），拖动它们即拖动小窗——空间不足时第二行先让出空间，其次是名称，AI 会话的标签从不让出，仍放不下的部分在其末端截断，而不会画到按钮下面；空白部分拖动窗口，双击则最大化窗口；在主窗口中有“向右分屏”与“向下分屏”——+ 选择器，在这个小窗的那一侧打开；有其他已打开的小窗时，先是列出它们的菜单，选中的那个放到这一个旁边，最后是打开选择器的“打开设备…”——，多个小窗的分组中有“最大化”（该小窗单独占满分组，其他小窗继续运行）或“还原”，以及关闭（×；单独的主页没有，因为它没有可关闭到的地方）。窄于 560 点的小窗把分屏与“最大化”收进 ⋯，每种分屏是一个子菜单，列出其他小窗与“打开设备…”（`foldedButtons`）。分组中焦点所在的小窗带强调色边框；焦点随键盘与点按进入小窗。
- **分组。** 每个打开的小窗都有自己的条目并显示出来。把小窗放在另一个小窗的边缘，即在那里把那个小窗一分为二——位于它的旁边、上方或下方——并加入它的分组，因此一侧可以是一个顶满高度的小窗，另一侧上下两个（`split`，小窗树；最多同时显示四个，第五个会替换一个位置）；放在小窗中间即替换那个小窗，被替换的小窗保留自己的条目；放在侧边栏的列表上，小窗即离开分组，得到自己的条目。只剩一个小窗的分组就是那个小窗的条目；条目清空后即消失，显示它前面的条目；什么都不剩时显示主页。分隔线可以拖动。
- **独立窗口：** 拖出 Kyokai 窗口的小窗会移到一个独立窗口中——只有一个小窗，没有侧边栏，从不分屏——小窗关闭时窗口随之关闭并断开连接；放到主窗口的侧边栏或小窗上即回到主窗口。macOS 上它的标题栏为红绿灯留出位置。
- **+ 选择器**（`pickerView`）：侧边栏（或图标栏）的 + 下方、或小窗标题栏的分屏按钮下方的弹出框。先选类型——桌面、SSH、远程桌面、VNC 或 AI 任务，保留上次所选——，然后按名称、设备 ID（空格不计）或地址搜索，然后是“设备”之下的设备（`pickRows`；只列出网络中的设备时不显示这个标题）：AI 任务时“这台电脑”排在最前（用它的 AI 开始一个新会话）；输入了没有设备拥有的设备 ID 时为“按设备 ID 连接”，输入了地址——带点或冒号，或者不匹配其他任何内容的一个词——时为“按地址连接”；本机连接过的设备，各带其路径（直连或中继及其延迟、已连接，或最近连接时间），最近一分钟的状态表明它打不开该类型时变灰并显示“…不可用”（`kindOffered`：服务没有应答或保存的登录信息不授予它；其 AI 未就绪或未授予），从不因为没有状态而变灰；桌面时最后是已加入的网络能到达、本机却从未连接过的 Kyokai 设备，带虚线图标，位于“在你的网络中”之下。底部是打开的位置——“单独打开”（自己的条目）或“在当前小窗旁”（与焦点所在的小窗分屏，或在打开选择器的分屏按钮所在小窗的那一侧分屏，此时选择器以“在当前小窗旁”打开）——以及打开按钮（“打开SSH”、“开始 AI 任务”…）。搜索框在打开时即接收键盘，选定类型后再次接收；↑ 与 ↓ 在能打开该类型的设备之间选择，Enter 打开所选的那个，否则打开第一个，Esc 或点按外部即关闭，Tab 可到达各类型及其他控件。
- **搜索**（`paletteView`）：在主窗口中按 Ctrl+K（macOS 上为 ⌘K），或点按侧边栏底部的放大镜，即在距窗口顶部 72 点处打开一个面板，窗口略微变暗：一个接收键盘的输入框，然后是按组列出的结果，每组最多六个，标题中标出输入的第一个词——本机（接受临时密码时可复制临时密码，以及“换一个密码”；可复制设备 ID）、已打开的小窗、设备（连接，或显示已打开的那个）、操作（连接到设备：+ 选择器；设置；隐藏或显示侧边栏；三种外观）与设置（设置搜索能找到的每项设置，打开其页面并滚动到它）。输入的每个词都必须出现在结果的标题、其下的一行或设置的说明中，不区分大小写；标题匹配的在组内排在前面；未输入时显示除设置以外的全部（`searchPalette`）。↑ 与 ↓ 循环选择，Enter 或点按打开所选的那个（密码与设备 ID 则为复制），Esc、点按外部或再按 Ctrl+K 即关闭。某台设备桌面的画面、远程桌面或 VNC 的画面，或 SSH 终端接收键盘期间，Ctrl+K 发往那台电脑（`keysAway`）；放大镜仍可打开搜索。选择器或搜索打开期间，没有画面接收键盘（`covered`）。
- **窗口按钮：** macOS 上红绿灯位于侧边栏的顶行之上，与顶部小窗的标题栏居中对齐（在独立窗口中位于其小窗的标题栏上）。Windows 上系统的按钮会位于窗口的角上、一半在小窗之外，因此窗口隐藏它们（`HideWindowButtons`），由界面在右上角小窗标题栏末尾的分隔线之后画出最小化、最大化或还原，以及关闭（`windowButtons`），最大化按钮带 Windows 11 的贴靠布局；设置面板盖住小窗时，它们留在原处，以浅色显示在变暗的窗口之上，从不挨着设置面板的 ×（以叠加层画出；标题栏为它们保留位置但不显示）。
- **全屏**只显示焦点所在的小窗，没有标题栏与侧边栏。

## 设置

- 设置从侧边栏底部的齿轮打开，也可以从通往它的地方打开——网络状态、AI 横幅上的“查看”、设备卡片的“已保存的密码与密钥…”——，从不参与分屏（`settingsSheet`）：它是最上层，一个盖住整个窗口（包括侧边栏）的面板，距窗口两侧 64 点、顶部 48 点、底部 32 点，下方的窗口变暗。它的标题栏只写着“设置”并带 ×；左侧是各部分——偏好：通用；这台电脑：访问、网络、安全与隐私、运行方式；AI：服务商；Kyokai：关于与更新——旁边是所选的页面（[结构](#结构)）。按 Esc、点按面板之外或 × 即关闭；它显示期间，没有画面接收键盘（`covered`）。
- **搜索**位于各部分上方：其中有文字时，标题或说明包含其中每一个词（不区分大小写）的设置取代各部分，标题匹配的排在前面，各自注明所在页面（`settingsHits`、`searchSettings`；每个条目都显示在它的页面上，由测试检查）；选择一个即打开它的页面，滚动到它并以浅色标出两秒。
- **页面**（`settingsPage`）是一个标题和一句说明它用途的话，宽度不超过 720 点，然后是各部分：一个弱化的标题，右侧可有说明或按钮，下面是一个圆角的行列表（`App.section`）。一行（`rows.row`）以图块中的图标开头（服务商为其首字母，设备为其头像），然后是标题和一句简短的话，最后是它的控件；较长的说明放在标题旁的小 ⓘ（“工作原理”）后面，以弹出框显示。表单、设备列表或只显示一次的密钥，在它所属的行下方单独占一行。正确密码授予的权限是可切换的图块，每行四个（`toggleTile`）。

## 结构

- **主页**（`homeView`），宽度不超过 1120 点（`homeMaxW`）：两张卡片并排（5 比 7；不足 640 点时上下排列）。**本机**——以标签显示的网络状态，按三位一组显示的设备 ID 及复制按钮，然后是遮蔽的临时密码，以图标提供“显示”（“隐藏”）、“复制”与“换一个密码”（只接受固定密码时，改为一行说明，未设置固定密码时为一条警告；不接受任何密码时，改为一行说明其他设备用密钥登录或询问你）；机密未持久化时显示提示；已保存的身份无法解锁时提供“重新开始”（旧存储移到一旁，此后保存一个新身份；`secrets.start_over`）。**连接到设备**——设备 ID 或地址（IP 地址或域名，用于接受地址直接连接的设备；询问对方是谁期间显示“正在查找该地址上的设备…”）与“连接”（也可按 Enter；按设备 ID 连接需要先加入网络），以及**打开为**：桌面、SSH、远程桌面、VNC 或 AI 任务（请求在对方电脑上运行 AI 任务的桌面），即“连接”要打开的内容（`connectAs`）——五个分段，卡片窄于最宽语言所需的宽度（440 点）时改为菜单。在 macOS 上，缺少“屏幕录制”、“辅助功能”、“输入监控”或钥匙串时显示**隐私权限**，像主页的其他部分一样带标题：一张卡片，其中的行与设置中“访问”列出的相同（`privacyList`）——每行带图块、一句话与“允许”，或“已允许”；较长的说明在 ⓘ 后面——；本次运行中请求过的权限还提供“重新打开 Kyokai”，因为 macOS 只在授权之后启动的引擎中计入新授权。在助手模式下，卡片首先说明这些是 Kyokai Helper 的权限，缺少的一项提供“重启 Kyokai Helper”。下方是**设备**及其数量，标题旁有“我的网络中的其他设备”（默认关闭，`gui.json` 中的 `others_in_networks`）与“全部”或“在线”：等高的设备卡片网格——每台设备一张，绝不是每个会话一张——每张至少 300 宽，每行一到三张（`homeColumnsFor`）。卡片包括：标题行（头像、名称——本机为它起的名称，否则为它的别名——其设备 ID 与系统、以标签显示的状态：已连接、正在连接、在线或离线，以及 ⋯）；它的路径，一个菜单（`cardPath`）：一个圆点，连接期间为正在使用的路径，否则为手动选择的路径（“… · 已指定”）或自动模式此刻会选的路径——“直连 · 12 ms”、以警告色显示的“中继 · 231 ms”、一个地址“192.168.1.20 · 2 ms”——上次尝试失败的原因，或最近连接时间；菜单中有“自动”、Kyokai 网络和每个地址及其当前延迟或无响应的原因，然后是“地址…”（[networking.md](networking.md)，“路径”）；它的实时状态；以及操作：已连接或正在连接时为“打开”，否则为“连接”（设备在线时为主按钮），然后以图标显示无需对方用户即可使用的操作（`cardActions`）：状态报告正在应答的服务对应的远程桌面、SSH 与 VNC，以及其 AI 就绪时的 AI（连接并使用 AI），每项都只在其状态表明保存的密码或密钥授予它时出现（`offers`）；对该设备最常用的排在前面（`Prefs.Uses`，只在本机计数），否则按上述顺序。其他一切都留在 ⋯ 菜单中，其中有“连接”、“连接并使用 AI”、“打开远程桌面 / SSH / VNC”、“地址…”（与“重命名”一样是设备上方的主页编辑卡片：设备的头像、路径是什么，对面是“路径”——与路径菜单相同的选择；每条路径及其延迟、上次使用的时间与达到的码率，地址可“移除”，各行之间有分隔线；一个用于添加地址的输入框（按 Enter 即添加），以及“完成”；主页可见时每 60 秒探测一次所显示设备的地址）、“重命名…”（只在本机显示的名称，在设备上方带设备头像的卡片中编辑，其输入框接收键盘——Enter 保存，Esc 放弃；留空则恢复设备自己的别名）、“已保存的密码与密钥…”（设置中的“安全与隐私”）、“忘记旧身份”（密钥变化后）与“移除”（断开连接，把它及其已结束的连接移出主页，并忘记其固定的密钥、保存的登录信息与本机为它起的名称）。打开“我的网络中的其他设备”时，下面接着是**在你的网络中**：已加入的网络能到达、本机却从未连接过的 Kyokai 设备，每台只列一次，取其最佳路径——直连优先于中继，其次延迟最低（`networkOthers`）——以虚线卡片显示设备 ID、网络与路径及其延迟，并带“连接”。
- **主页上的实时状态：** 主页显示期间（主窗口可见，显示着主页小窗且设置已关闭），界面为最近的设备租用一次查看（`watch.set`，最多八台，每 10 秒续租，主页隐藏时撤回）；打开了状态小窗的被控端会留在租约中并排在最前，无论主页是否显示（`watchLease`）。被查看设备的卡片显示四个数值（`compactFigures`）：CPU 当前占用、内存已用与下载速率，然后是电池，否则为 GPU，再否则为磁盘可用空间——各有名称、数值与单位，以及一条以该指标颜色显示的细条（CPU 蓝色；内存绿色；GPU 红色；磁盘橙色；网络青色，其细条以最近两分钟的最高值为满；电池绿色，电量低时橙色）。点按它们会把该设备的**状态**作为单独的小窗打开（`statusTab`，“NUC · 状态”，像任何小窗一样列在侧边栏中）：仿照系统监视器 Pulse 完整显示每个指标，最多三个并排，各带以其颜色显示的图标与名称、说明（“当前”、“已用，共 16 GB”、“可用，共 512 GB”、“正在下载”、“正在充电”）、数值、三个较小的数值（CPU：应用、系统、核心数；内存：已用、可用、总量；GPU：历史的平均值与峰值；磁盘：读取、写入、已用；网络：正在上传、已接收、已发送），以及以点阵历史显示的最近两分钟——一列列圆点，最新的在右，每列从底部点亮到其数值所达的高度，堆叠指标的各部分使用各自的颜色（`dotHistory`）；被控端没有可报告的 GPU 与电池时将其隐藏，运行时间显示在名称旁。绝不把过时数据当作当前数据：6 秒以内的样本照常显示；6 到 60 秒之间数值变暗并显示“N 秒前更新”；更旧则不显示数值，只显示“HH:MM 时的状态”，历史清空。没有样本时卡片说明查看的进展：带加载指示器的“正在获取状态…”、没有保存的密码或密钥、需要对方安装 Kyokai 0.4.1，或被拒绝。
- **确认：** 等待被控端用户确认的控制端以强调色的卡片显示在小窗上方：其头像、“…请求连接”、其设备 ID 与是否连接过，对面是“拒绝”与“允许”（主按钮）；未使用密码、另一个密钥冒用本机已知的设备 ID，以及在 macOS 上所请求的功能缺少“屏幕录制”或“辅助功能”时，显示一个警告框；然后是它请求的权限，以可切换的图块显示，一开始全部打开，每块不窄于 140 点时与卡片同宽，否则排成尽量少且尽量均匀的几行（`askColumns`）——关掉的图块不在“允许”授予的权限之内。同时发出通知并把窗口带到前面。
- **已连接到本机：** 另一台设备连接到本机（或正在恢复）时，小窗上方有一张警告色的卡片写明是哪台设备、其设备 ID 与它可以做什么，并提供“断开”。
- **AI 服务商**（`aiProviders`）：新任务的默认设置——模型（所有来源的所有模型，以 `厂商: 模型` 名称列出）与“操作前询问”（批准方式）；服务商——标题旁是模板选择与“添加服务商”，每个来源以其首字母显示，带模板、模型数与密钥状态（已保存密钥、没有密钥、无需密钥）、“编辑”与“移除”；编辑器在它的行下方（新来源的在最上方），包括名称、地址（模板的各站点按名称列出）、自定义时的格式、只写的密钥、带“移除”的模型列表、要添加的 id 与“列出模型”（已保存的来源）；其他设备——通往“访问”（保护模式下不显示）；AI 会话：“发送提示的按键”（Enter、Shift+Enter 或只用发送按钮；`gui.json` 中的 `send_key`）与带“清除历史”的“最近的任务”（本机的历史与本机保存的会话，正在小窗中打开的除外）。任务本身是 AI 会话的小窗（[AI 会话](#ai-会话)）。本机的任务等待批准期间，小窗上方一张强调色的卡片带“查看”（其会话的小窗），并发出通知；控制端的任务在本机工作期间，一张警告色的卡片写明是哪台设备，并带“查看”与“停止”；正在显示跟随该任务的会话时两者都不显示。
- **网络：** 首先是网络的整体状况（`networkSummary`）：在线、正在连接、无法连接或离线，以及已加入的网络中有几个已连接。然后是**网络**——保存的网络（最多 8 个；标题旁有“添加网络”），ⓘ 中说明本设备在每个网络中的设备 ID 都相同。
  每一行显示它在此显示的名称（或网络名称），其下是网络名称与实时状态——已连接时为它的 Kyokai 设备、虚拟地址、用通俗说法描述的 NAT 类型与监听时直接连接的端口；正在连接；以危险色显示的“无法连接”及原因；或未加入——然后是“已连接”、
  “加入”开关（立即生效；被拒绝时显示引擎给出的原因，随后页面重新读取网络）与 ⋯ 菜单（“编辑”与“移除”：确认后 Kyokai 离开该网络，并忘记它的服务器、名称和密钥）。已连接的网络下方是它能路由到的 Kyokai 设备
  （设备上次在本机会话中给出的名称（若有）、设备 ID、直连或中继、延迟、“复制”与“连接”；ⓘ：设备宣告的 ID 不能作为证明）。“添加网络”和“编辑”在行下方打开同一个表单：在此显示的名称（可选）、服务器（每行一个 URL）、网络名称和只写的密钥字段（留空保留已存的密钥；
  弱密钥会被标出），以及“保存”（有服务器和名称时才可用）与“取消”；被拒绝的设置会显示引擎给出的原因。**其他进入方式**：“接受地址直接连接”，默认关闭，打开时显示接受的网段，每行一个，带“保存”与“取消”；无法监听时该行给出警告。最后是**高级**：“尝试直接连接”（默认关闭；助手模式下固定打开；切换后立即生效，[networking.md](networking.md)），其 ⓘ 警告它会让本机监听端口、更容易被发现，而选择协议不会如此；以及“延迟优先路由”。
- **设备名称：** 设备出现的每个地方（确认请求、主页的设备、小窗与侧边栏、受信任设备、查看窗口标题、网络页面）都会在设备 ID 旁显示它的名称——本机用户为它起的名称（`gui.json` 的 `aliases`，从不发送到任何地方），否则为它自己的别名——而不是代替设备 ID，
  并带有圆形头像（`deviceAvatar`）：设备的厂商、型号、别名或系统（按此顺序尝试；只匹配完整单词，因此 `hp` 不会匹配 `php-dev`）
  指明某个已知厂商或系统时（`deviceLogoName`）显示该厂商的单色标志，否则显示别名的首字母。厂商标志是其所有者的商标，只用于表明设备的厂商；
  来源列在 `internal/gui/assets/logos/SOURCES.md` 中（见 [packaging.md](packaging.md) 的“厂商标志”）。
- **访问：** macOS 上首先是“隐私权限”，每项带“允许”（ⓘ：macOS 会询问什么，以及授权在重新打开 Kyokai 后才生效）。**登录方式**，各自开关、可任意组合：临时密码（主页上显示的那个）；固定密码——“已设置。”、“未设置。”，或在打开却未设置时显示警告——其“设置…”或“更改…”在它下方打开表单（只写，“保存”、“移除”、“取消”）；以及密钥——显示可连接的数量，“管理”在它下方列出每一个：名称及其类型与 `SHA256:` 指纹、“复制公钥”、确认后“移除”与它自己的开关，然后是“添加密钥”（一行 OpenSSH 公钥或 `.pub` 文件，以其注释命名）与“生成密钥对”（公钥可连接本机，私钥只在本页面显示一次，绝不保存）。一项都不打开时每次连接都会询问，电脑前没人时谁都进不来（会给出警告）。**密码正确时**：“无需确认即可连接”，默认开启，让打开的登录方式无需确认即可接入——电脑前没人时只有固定密码或密钥可以——；它打开时，“使用正确密码时”以图块显示密码无需确认即可授予的权限（查看屏幕、鼠标和键盘、剪贴板、复制文件、听到声音、运行 AI 任务、批准 AI 操作、查看状态、SSH、远程桌面、VNC；“查看状态”默认开启，各项服务默认关闭），标题旁写着“其他一切都等你确认”。**本机服务的端口**：SSH、远程桌面与 VNC 各一个端口，留空即标准端口，编辑时有“保存”与“取消”。然后是正在查看本机状态的设备及其开始时间；受信任设备及其最近连接时间与“移除”；以及**声音**：共享的声音——未选择输入设备时为本机正在播放的声音，已不在的设备显示为当前未连接，选择输入时向 macOS 请求“麦克风”权限。
- **安全与隐私：** **设备身份**——设备 ID 带“复制”，别名带“保存”，指纹带“复制”，通过文件对话框以口令备份和恢复，以及在警告后重置；**你的密钥**，标题旁是“生成密钥”与“导入密钥”（名称、类型与 `SHA256:` 指纹、“复制公钥”、确认后“移除”；生成——Ed25519，私钥以 OpenSSH 格式只显示一次，带“复制”与“保存到文件…”，用给出的口令加密，之后由引擎保存；导入——粘贴或来自文件，OpenSSH 或 PEM，加密的密钥会要求口令；支持 Ed25519、2048 位及以上的 RSA、ECDSA P-256 或 P-384）；**已保存的密码与密钥**（每台保存了内容的设备：每项登录信息一个标签——Kyokai 密码、接入所用的密钥、每项服务的登录信息——带 × 可忘记这一项，以及“全部忘记”）；**隐私**：在屏幕采集中隐藏 Kyokai——默认打开，立即作用于主窗口和每个查看窗口并告知引擎，macOS 上引擎的采集随之改变；关闭后（先警告），控制这台设备的人的输入也能到达 Kyokai 的窗口，AI 的永远不能，有请求或批准在等待时任何人的都不能——，完全无日志——默认关闭，打开前警告此后无人能知道谁连接过、本机连接过谁，正在使用的引擎尚不支持时给出提示——，机密的保存方式，以及保护模式（仅在设置了固定密码时可用，需确认）。
- **通用：** **语言与外观**——语言，以及外观（侧边栏的按钮也可切换）；**启动与关闭**——登录时打开，默认关闭（登录时启动的 Kyokai 不显示窗口，只显示托盘图标；Mac 上作为登录项，在应用就绪后才询问：更早询问时 macOS 回答“否”）、“登录时启动后隐藏到托盘”（默认打开），以及关闭按钮。
- **运行方式：** 免授权、随界面与后台服务三行，使用中的那一个带标记，其他的带“切换”（“随界面”的 ⓘ：那一次管理员提示以及哪些内容会随之迁移）；切换在后台进行，期间显示加载指示器，完成后以提示告知（[run-modes.md](run-modes.md)；Windows 与 macOS）；助手落后于应用时有一行带“更新”。本配置文件自己的引擎处于驻留状态时（身份已迁往 Kyokai Helper，而它已不在），每个页面都显示一张卡片，可重新安装助手或在此重新开始。
- **关于与更新：** **Kyokai**——版本带“源代码”，许可证带“显示”随附的开源声明；**更新**——新版本带“安装并重启”、安装进度，或已安装的版本带“检查更新”，以及每日检查；**诊断**——版本与 ABI、引擎启动时间、运行方式、数据文件夹及“打开文件夹”、日志文件夹及“打开文件夹”与“保存日志…”（把经 `logs.read` 取得的引擎日志、助手模式下只有管理员才能打开的助手及其代理的日志，以及本界面自己的日志放进一个文本文件），完全无日志时显示“已关闭”。
- **保护模式：** 主窗口只有一个小窗，没有侧边栏：一张卡片——盾牌图标、保护模式是什么，对面是固定密码输入框与“关闭”（也可按 Enter；密码错误时会提示）——在本机的 AI 会话（[AI 会话](#ai-会话)）上方；其标题栏的齿轮打开只有 AI 页面的设置。确认请求与已连接到本机的设备仍会显示。
- 引擎会话连接之前，需要它的页面在原处居中显示“正在启动…”，或引擎没有运行及其原因（`emptyState`）；身份已移到 Kyokai Helper 而助手不在的配置以同样方式说明，并提供“安装 Kyokai Helper”与“在此重新开始”。
- **应用更新（关于与更新）：** 每日检查（可关闭）与“检查更新”读取 GitHub 最新发布的已签名更新；“安装并重启”会先停止引擎，
  就地安装后重新启动。开发版本会说明无法自行更新。

## 连接

- 每台设备一个连接，从一开始就显示为一个小窗，就像 RustDesk 显示为一个标签页。连接会在主窗口中以单独的条目打开它的小窗，小窗中间是一张主页样式的卡片，带设备的头像与名称：“正在连接…”；询问设备的用户时显示“等待对方设备允许…”，并附“或输入对方的密码”、“记住密码”与“连接”（等待中的请求会被放弃，因此设备同时只有一个请求）；然后是画面。连接结束或失败时，小窗说明原因（包括密码错误），并附密码栏与“重新连接”。密码留空时使用为该设备保存的密码，否则询问其用户。关闭小窗（×）即断开连接，正在连接或等待设备用户时也是如此：该请求立即结束，不会以单独的小窗再出现。小窗如何移动、分屏与得到独立窗口：见[窗口](#窗口)。每个显示中的小窗都保持连接运行；只有焦点所在的小窗接收键盘与剪贴板；在映射与翻译模式下，按键送往画面位于指针下方的小窗，它随之获得焦点；在每种模式下，画面（远程桌面或 VNC 的画面也是如此）中控制端的输入法都是关闭的（[computer-use.md](computer-use.md) 的“键盘模式”）。小窗可以是一台设备的桌面，也可以是它的某项服务（SSH、远程桌面、VNC；`viewer`、`serviceTab`），每台设备每种一个，每种都同样可以拖动、移动与关闭。
- 服务小窗（[remote-services.md](remote-services.md)，“客户端”）的标题栏为设备名称，旁边是服务。它先显示带加载指示器的“正在连接SSH…”，没有记住的方式时显示登录表单：登录方式（分段选择——SSH：密钥、密码；VNC：仅密码、用户名和密码、无需登录；远程桌面：用户名和密码、在远程屏幕上），该方式需要的字段（用户名；远程桌面另有域；密码），“密钥”与无需登录方式的说明，“记住”，以及“取消”与“登录”（字段填好之前“登录”不可用），然后是客户端：SSH 为 MyGo 的终端，采用应用的浅色或深色主题；远程桌面与 VNC 为对方桌面的画面，控制栏有“显示”（适应窗口或原始大小）、“键盘”（键盘模式）、“操作”（Ctrl+Alt+Del）与“全屏”。结束时说明原因并提供“重新连接”；SSH 服务器的密钥变化后还提供“信任新密钥”。
- 画面在黑色背景上按比例显示，或选择“原始大小”时按被控端每个像素一个点显示，比窗口大时可双向滚动（拖动滚动条移动；会话控制被控端时滚轮发送到被控端），比窗口小时居中；用一个跟随鼠标的小圆环标出被控端的指针。与 RustDesk 一样，一条控制栏浮在画面顶边上：拖动它的拖动柄（或控制之间的空隙）可沿顶边移动它，松开的位置对所有查看窗口记住（`gui.json` 中的 `toolbar_at`）；⌃ 把它收起为同一位置上的一个小把手（拖动柄与 ⌄），按设备保存。它的图标各由提示说明名称：“显示器”（被控端有多个显示器时按编号选择；“适应窗口”或“原始大小”）、“画质”（预设、“帧率”下的上限如“30 fps”、有可选项时“编码”下的“自动”以及两台电脑都支持的编码（只显示编码名称），以及“全彩”）、“键盘”（拥有 `control-input` 时，在 Windows 与 macOS 上：键盘模式映射、翻译或传统，对所有查看窗口记住；任一端是 Mac 时还有“交换 Ctrl 与 Cmd”；Mac 上没有 Kyokai 的“辅助功能”权限时图标显示为警告色，其提示说明要允许它）、“操作”（拥有 `control-input` 且被控端提供时，即 Windows 被控端：锁定屏幕、助手模式下的 Ctrl+Alt+Del、“阻止对方的键盘和鼠标”与“隐私模式”，按被控端报告的状态勾选），然后是“声音”（播放被控端的声音；未选择时打开，按设备保存）、“指针”（显示或隐藏圆环，对所有查看窗口记住）、“剪贴板”（拉出剪贴板面板，拥有 `clipboard` 或 `files` 时）、“AI”（在桌面旁边的小窗中打开该设备的 AI 会话：已打开的最新一个，否则新建一个）与“全屏”这几个开关；窗口较窄放不下的进入控制栏的 » 菜单。它们旁边是路径：一个圆点与会话所走的地址（`sessions[].route`），否则为直连或中继（中继显示为警告色，其提示建议在两台设备上都打开直接连接），以及被控端测得的延迟，提示中还有尺寸、编解码器、帧率与码率，用什么编码、用什么解码（各自按其报告为硬件或软件），以及时间花在哪里（被控端的编码、网络、本机的解码与绘制、帧率与被控端目标帧率的对比）——对于不能录制屏幕的被控端发来的测试图案，则是一个警告标志，说明“这是占位画面”。第一幅画面到来之前，画面区域显示“正在等待画面…”；被控端在发送帧、却 2 秒没有画面到达时，画面底边附近的一条横幅在上一幅画面上显示“正在恢复画面…”。显示占位画面的被控端则在黑色的画面区域上（而不是彩条）显示一条状态，说明被控端所说的情况：它的屏幕已休眠或已关闭、正在被唤醒，没有可显示的屏幕，Kyokai Helper 正在准备，画面正在重新开始，没有共同的编码，或屏幕无法共享。被控端说其显示器已变暗或休眠时，拥有 `control-input` 的会话提供**唤醒**——不说明这一点的较旧被控端则在等待或恢复 3 秒之后提供（[computer-use.md](computer-use.md) 的“睡眠”）。引擎因落后而拒绝输入期间，路径前面会以警告色显示“输入已暂停——连接跟不上”，半秒后键盘抓取会让开（[computer-use.md](computer-use.md) 的“输入”）。在控制栏中做出选择后，画面重新接收键盘；画面上的鼠标、滚轮与键盘操作会发送到被控端（[computer-use.md](computer-use.md)），在控制栏上按下则永远不会。画质预设、帧率上限、“适应窗口”或“原始大小”、“全彩”、“编码”、“交换 Ctrl 与 Cmd”、剪贴板开关以及控制栏是否收起按设备保存（`gui.json` 中的 `viewers`）：设备的查看窗口以上次为它选择的设置打开。
- 剪贴板面板：“与这台设备共享剪贴板”（除非关闭，否则打开，按设备保存），以及该设备的小窗位于前台期间经过剪贴板的内容，最新的在前（最多 30 条，只在内存中，关闭小窗即消失）：每条的来源——来自该设备（被控端）或来自本机（控制端）——与时间，然后是文本及“复制”、图片的缩略图及其尺寸，或文件的名称、数量与大小；“清除”清空列表。只有位于前台的小窗——最近使用的 Kyokai 窗口中焦点所在的那个；那是主页时则没有——交换剪贴板（[computer-use.md](computer-use.md)，“剪贴板”）；小窗不在前台时面板会说明。
- 桌面的连接请求查看、输入、剪贴板、文件与声音。它的 AI 是旁边一个会话的小窗（控制栏的“AI”），通过它自己的链接（[AI 会话](#ai-会话)）。

## AI 会话

- AI 会话是一个小窗（`aiTab`）：与本机或某台被控端的 AI 的对话，其任务在该设备上运行（[computer-use.md](computer-use.md)，“AI 任务”）。一台设备可以有多个会话；它的任务一次运行一个，因此要在另一个任务工作时开始任务的会话会说明这一点（“Studio Mac 正在执行另一个任务。”），并带“显示它”。会话可以从 + 选择器（AI 任务，“这台电脑”在最前）、搜索中的“新 AI 任务”、主页的“打开为 AI 任务”与卡片上的 AI、桌面的控制栏（在其旁边）以及最近的任务打开。
- **标题栏**与其他小窗相同：强调色的 AI 图标、设备名称（“这台电脑”或被控端的名称），其他小窗写类型的位置写会话的标题——重命名之前为它的第一条指令（之前为“新 AI 任务”）——，然后是“重命名”（在原处输入标题：Enter 保留，Esc 保持原样），任务等待批准或已暂停时还有标签“等你处理”或“已暂停”；被控端的会话另有“查看它的屏幕”（小窗较窄时只显示图标），在会话左侧打开被控端的桌面。
- **新会话**居中显示，最宽 680 点：AI 的圆形标志、“要 AI 在这台电脑上做什么？”（或在被控端上）及它在那里如何工作（“它能看到这块屏幕，并使用鼠标和键盘。移动你的鼠标会立即暂停它。”）、输入框、三条可填入输入框的建议（整理“下载”文件夹、按日期重命名这些照片、找到上个月的发票并打印），以及“最近的任务”——本机的任务与本机保存的与其他设备的会话，最新的在前，最多六个（`recentAI`），每行写出标题、运行的位置与状态：“等你处理”显示为标签，否则为一个词的状态及时间（今天的为时刻，“昨天”，再早为日期；`aiWhen`）——点按即打开其会话。
- **对话**最宽 720 点：你的指令在右侧，底色为小窗的浅色；任务最近 20 个步骤按从此小窗发送的回复分组，每组以步骤数开头（“4 个步骤”），点按可收起；每个步骤带一个圆形标记（已运行为对勾，失败或被拒绝为警告色的叉，未运行为短横）、以文字写出的操作、未按要求运行时的结果，以及时间；每条回复跟在它所回应的回答之后——任务只保留最新的回答，小窗会保留之前的——最新的回答在最后；工作时的进度说明；内联的等待批准的步骤，以强调色框出并带盾牌图标——它要做什么、服务商的说明、“允许”与“拒绝”，以及“在 NUC 上移动鼠标会立即暂停 AI。”（会话无权批准时，说明由被控端用户决定）；以文字写出的状态及模型，以及失败的原因。它随内容增长跟随到末尾。步骤不带缩略图：任务记录不保存截图，0.6.0 也保持线路协议不变。
- **输入框**位于底部，出现时即接收键盘：一个最多增长到约七行的文本区域；其下方、框内是发送方式的说明（“按 Enter 开始”、“Enter 发送 · Shift+Enter 换行”、相反的说法，或只用发送按钮时不显示：设置中的 AI 服务商；`OnTextKey`、`sendsOnEnter`、`aiSendHint`），以及圆形的“发送”——任务工作时则为“暂停”或“继续”与圆形的“停止”。它开始会话的任务，任务完成后回复它（引擎只能让已结束的任务继续），或在停止或失败后重新开始。设备下一个任务的草稿在输入时实时共享（本机的与其控制端共享，被控端的经由被控端与其用户和其他控制端共享；在此处输入后的一秒内优先）。输入框上方说明无法发送的原因：那里有另一个任务在工作（显示它）、本机没有带密钥的模型（设置），或被控端的链接正在连接、正在等待其用户允许 AI 任务、被拒绝或不允许 AI 任务（重新连接）。
- **输入框下方的标签**（`chips`）：本机为“操作前询问”与模型，两者都是菜单，选择即更改本机的 AI 设置，另有“这台电脑”；被控端为“批准方式按 NUC 的设置”、带链接状态圆点的“在 NUC 上运行”，以及任务的模型和所用的密钥（“Claude Opus 5.5 · NUC 的密钥”；任务说明之前为“NUC 的模型与密钥”）。新会话的位置标签是一个菜单，列出这台电脑与本机连接过的设备，选择即把会话移到那里（`moveTo`）。
- **被控端的链接**（`aiLink`）：每台被控端一个，由其会话的小窗共用，最后一个关闭时结束；它是一个只请求 `run-ai-task` 与 `approve-ai-action` 的独立会话，因此被控端不发送画面；它的媒体连接带来被控端的任务（每个控制端看到的同一份记录）、共享的草稿与拒绝原因，并送出请求。持有活动链接的小窗在关闭其窗口时计为一个连接；链接结束会暂停它在被控端开始的任务，与任何控制端离开时一样。
- **保存在本机**（`gui.json` 中的 `ai_sessions`，最新的 50 个）：每个会话的 id、设备、跟随的任务、标题、状态与时间——绝不包括截图；完全无日志打开时只在内存中。从未开始任务的会话在其小窗关闭后不保存。

## 视觉语言

- MyGo 浅色/深色主题加系统强调色；布局数字与颜色在 `style.go` 中命名。侧边栏位于窗口的材质之上，小窗位于主题的背景上。
  图标是 `internal/gui/assets/icons` 中的原创线条图；Windows 上自绘的窗口按钮仿照 Windows 11 的字形。
- 正文 14，标题 20–24，不小于 12；设备 ID 为 34，使用等宽数字。
- 正在进行的事情都显示同一个加载指示器：MyGo 加载插件中 loading-dev 的 Arc，使用强调色（在查看器的黑色背景上为
  白色），并以正在加载的内容为辅助技术命名。
- 应用图标为原创作品：一个被边界线（鏡界）分开的圆环，一侧实心、一侧描边，一个指针跨过边界。托盘以单色模板图形
  显示同一标志：白色；Windows 以浅色绘制任务栏时（`SystemUsesLightTheme`，每次状态更新时检查）改用黑色（`tray-black.png`）；macOS 自行为模板着色。
  `go run ./tools/icon resources/icon.png internal/gui/assets/tray.png` 按其几何形状绘制全部图形。

## 托盘

- 菜单：设备 ID（不可点）、有任务进行时的“停止 AI 任务”（紧急停止）、显示 Kyokai、退出 Kyokai。从不显示密码。
- Kyokai 的窗口不参与屏幕采集，因此查看窗口和 AI 任务都看不到它们，远程输入也到达不了它们，除非关闭了“安全”中的“在屏幕采集中隐藏 Kyokai”（AI 永远到达不了）。
- 主窗口只在显示时存在：在托盘中启动的 Kyokai 不创建主窗口，关闭到托盘会结束它（其位置与大小会留给下一个）；“显示 Kyokai”、再次启动、连接请求、连接的小窗或程序坞会重新创建它。留待以后的隐藏窗口曾在 Windows 登录时以 Kyokai 当作隐藏的白色框出现：显示器变化（锁屏、显示器变暗、KVM 的显示器恢复）时 Windows 对窗口的重新排列让它绕过 MyGo 变得可见。在 Windows 上，界面日志会记下 Kyokai 每个变为可见的窗口。
- 关闭窗口会把 Kyokai 放进托盘，并在第一次时说明；没有托盘，或关闭按钮选择“退出”时，关闭即退出。退出应用本身（应用菜单、程序坞、注销或关机）总会退出，从不询问，并让引擎结束本界面的连接（`sessions.close_controllers`，最多等一秒）。
- 关闭窗口时由 `decideClose` 决定：关闭按钮选择“退出”时，关闭主窗口会在任何地方有活动连接时询问，然后退出；否则，窗口中有两个或以上活动连接（正在连接、等待中、已连接或正在重连；桌面与服务一样），或有一个看不到的连接（它的活动小窗都没有显示）时询问，然后断开其中的小窗并关闭（主窗口则关闭到托盘）。询问是一个列出这些连接的对话框，带“断开并关闭”（或“断开并退出”）与“取消”。
- 在 macOS 上，只有打开着 Kyokai 窗口（主窗口或连接的单独窗口）时程序坞中才显示图标；只剩菜单栏图标时，Kyokai 会离开程序坞与应用切换器，打开窗口后图标随之回来。
