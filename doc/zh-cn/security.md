# 安全

## 机密存储

- 核心把所有机密放在一个 JSON 映射中，用 XChaCha20-Poly1305（24 字节随机 nonce，附加数据 `kyokai/secrets/v1`）加密后
  原子写入 `secrets.bin`。
- 32 字节主密钥来自操作系统：Windows 上为当前用户的 DPAPI 数据块（`master.key`），macOS 上为登录钥匙串中的通用密码
  （服务 `com.yuanzhe.kyokai`，账户 `master-key` 或 `master-key.<profile>`；macOS 的助手以 root 身份放在系统钥匙串中，随其状态一同删除）。
- 系统凭据存储不可用时不持久化任何内容：机密只在本次运行的内存中，界面会说明设备 ID 将改变。已存在但无法解密的存储
  从不被覆盖；本次运行使用临时身份并说明这一点，“重新开始”会把它移到一旁（`secrets.bin.unreadable-<time>`，保留），换成一个此后一直保存的新存储与新身份。在 macOS 上只在钥匙串项目不存在时才新建：用户拒绝访问已有项目时不替换任何内容，
  本次运行把机密保存在内存中（持久化状态 `denied`），权限卡片上钥匙串一行的“允许”会再次打开存储——macOS 会再次询问——并在其上重建核心。
- 机密在释放时清零；`kyokai_stop` 会全部丢弃。
- 存储中保存设备密钥、含网络密钥的网络设置（[networking.md](networking.md)）、OPAQUE 服务器密钥与固定密码的记录、受信任设备、
  已知被控端与为被控端保存的密码（[identity-and-access.md](identity-and-access.md)）以及 AI 服务商的 API 密钥。本地 API 只把网络密钥从界面（或
  `ctl`）传给引擎，从不回传；`ctl` 从环境变量而不是命令行读取它。固定密码与连接时输入的密码同样如此（`KYOKAI_PERMANENT_PASSWORD`、
  `KYOKAI_PASSWORD`）；核心只在该会话结束前把用户输入的密码保留在内存中，随后将其清零。
  服务商密钥同样如此传递（`ctl ai-key` 使用 `KYOKAI_AI_KEY`），且从不返回。

## 剪贴板

共享需要 `clipboard` 权限，只从会话开始后的复制开始，且绝不提供 Kyokai 自己复制的文本（[computer-use.md](computer-use.md)）。

文件需要单独的 `files` 权限。接收的一端在写入任何内容之前检查所提供的每个路径（不允许绝对路径、`..`、保留字符或设备名，不允许重复）
与限制（1000 项、1 GiB），只在为本次会话创建的文件夹内写入、只新建文件（从不覆盖），并在会话结束时删除该文件夹。
发送的一端从不跟随链接或联接点。在助手模式下，文件在模拟控制台上已登录用户身份的情况下读写，因此放在剪贴板上的路径不会赋予该用户本来读不到的东西。

## AI 任务

- 模型使用被控端的服务商账户：每个来源的密钥只经 HTTPS 发给该来源（明文 HTTP 只允许发往本机上的服务器，且它不需要密钥），绝不进入日志、错误信息、状态、历史或其他设备。
- 截图只在任务对话期间存在于内存中，只发给所选的服务商；历史（`ai-tasks.json`）保存指令、模型的文字与操作，绝不保存图片。
  Kyokai 自己的窗口不参与采集（`SetContentProtection`），因此 AI 页面与批准提示不会到达模型。被控端用户可以在“安全”的“隐私”中关闭此项
  （通用，“在屏幕采集中隐藏 Kyokai”，默认打开），以便在无人值守的电脑上通过其他远程桌面工具查看和更改 Kyokai；
  此时这些窗口会出现在所有采集中，包括 Kyokai 自己的视频和 AI 的截图。输入仍然绝不会到达它们。
- 模型的提议只能是输入：每个操作都要经过解析、对照最近一张截图检查范围，并由被控端自己的执行器执行；不会运行任何命令或代码，
  也不会向 Kyokai 窗口注入任何输入（指针输入按其下方的窗口判断，按键按拥有焦点的窗口判断）。
- 本地输入、暂停、取消与紧急停止会立即收回任务的输入租约；之后才到达的响应绝不会执行（[computer-use.md](computer-use.md)）。
- 控制端的任务使用被控端的密钥、按被控端的批准方式运行；控制端需要 `run-ai-task` 才能启动或控制任务，需要 `approve-ai-action` 才能批准；
  被控端只保留一份 AI 记录，因此有这些权限的控制端可以控制被控端的任务，无论由谁发起。被控端用户能看到每个任务，并可以暂停、停止或批准其中任何一个。

## 设备身份

- 一把 Ed25519 签名密钥，由系统随机源生成，保存在机密存储中。
- 设备 ID 由公钥推导：对 `kyokai/device-id/v1` 与公钥做 SHA-256，取前 8 字节为数，再归约到 100 000 000–999 999 999。
  它用于定位设备，从不证明设备身份。指纹（公钥的 SHA-256）才是完整身份。

## 临时密码

从 `abcdefghijkmnpqrstuvwxyz23456789`（不含 0、1、l、o）中取 8 个符号，约 40 位，来自系统随机源。它只存在于核心内存中，
每次启动和按需更换，只有用户显示或复制时才传给界面；一个随机序号告诉界面它已变化而不泄露它。

## 日志

日志记录版本、设备 ID 与机密的保存方式——从不记录密码、密钥或机密。引擎在状态目录写入 `logs/engine.log`。2026-10-17 审查：
引擎记录它的启动（版本、设备 ID、机密的保存方式）与停止原因（生命线或父进程消失）；核心不写日志；服务商的错误只带状态与消息，绝不带密钥。Go 的崩溃跟踪（在 `engine.log` 中，界面的在 `logs/gui-crash.log` 中）只含调用栈与运行时的消息，不含机密。macOS 助手的 launchd 任务把它的 stderr 写入其状态目录中的 `helper.log`。

### 完全无日志

“安全”的“隐私”中的**完全无日志**（默认关闭；打开前会先询问，并警告此后无人能知道谁连接过、本机连接过谁）让 Kyokai 在电脑上留下尽可能少的内容。界面及其引擎（用户引擎或助手，每次连接引擎和设置改变时以 `logs.set` 告知）随后：

- 不写任何日志或崩溃跟踪：状态目录中的 `no-logs` 标记让在那里启动的每个进程都不打开日志，崩溃输出被关闭，stderr 被送往空设备（否则 launchd 会把它保存在 `helper.log` 中）；
- 删除已经写下的日志：`logs` 文件夹与 `helper.log`（launchd 在助手每次启动时会创建一个空的，由助手删除）；
- 只在内存中保留连接记录（`access.history`）：受信任设备与已知被控端从机密存储中移出，引擎停止后即消失，因此重启后，带着新密钥的已知设备 ID 不会再被标出，“最近”也从空开始。这一选择本身（`no_history`）会被保存，所以下次启动同样不保留。

保存的密码、为设备起的名称、按设备的查看设置以及 AI 任务历史属于用户自己的设置，会保留。系统自己写入的报告（macOS 在 `~/Library/Logs/DiagnosticReports` 中的崩溃报告、Windows 错误报告）不在 Kyokai 的控制范围内。关闭完全无日志会把本次运行的连接记录重新写入存储，此后照常记录日志。

## 本地 API

只服务引擎自己的用户（依据对端凭据，从不依据请求内容）；见 [architecture.md](architecture.md)。特权助手的套接字所有本地用户都能打开，
而助手只服务 SYSTEM、它的操作者与 `kyokai` 组，依据调用方的令牌（其用户与已启用的组）判断；不在其中的管理员同样会被拒绝
（[run-modes.md](run-modes.md)）。

## 威胁模型

| 资产 | 威胁 | 缓解 |
|---|---|---|
| 与被控端的会话 | 网络成员或中继冒充设备、读取或篡改流量 | 在 EasyTier 之上端到端的 Noise XX，每个静态密钥由设备密钥签名；首次使用时固定被控端密钥；密钥变化即拒绝 |
| 被控端的密码 | 在线或离线猜测 | OPAQUE（无法从线路上离线猜测），按地址的速率限制以及不影响已固定密钥的全局退避，超出密码授予的权限时需要被控端确认 |
| 权限 | 控制端做超出授予范围的事 | 每个请求都在被控端按会话的权限检查；任何权限都不隐含另一个；加入网络不授予任何权限 |
| 服务商密钥与机密 | 经日志、状态、会话或文件泄露 | 在本地 API 上只朝引擎方向传递，保存在机密存储中，从不记录或返回 |
| 由 AI 操作的被控端桌面 | 模型（或屏幕上引导它的文字）违背用户行事 | 提议只能是输入，由被控端校验并执行；批准；本地输入与接管会立即暂停；迟到的响应绝不执行；Kyokai 的窗口既不被采集也不会被注入输入 |
| 旧消息 | 重放输入、命令或登录 | Noise 的 nonce；续接令牌一次性、绑定控制端密钥、有效 2 分钟；重新连接后命令绝不重发；任务启动是幂等的 |
| 被撤销的设备 | 重新进入 | 撤销会结束它的进行中会话并丢弃它的续接令牌；会话结束时它的任务会暂停 |
| 本地 API | 本机其他用户操控引擎 | 对端凭据，只服务引擎自己的用户 |
| 助手 | 本地用户操控 SYSTEM 服务，或替换它运行的文件 | 对端凭据，只服务操作者与 `kyokai` 组；它的文件是只有管理员能修改的副本；状态文件夹只对 SYSTEM 与 Administrators 开放 |
| 助手更新 | 本地用户替换应用的文件，让 SYSTEM 运行它们 | 发布密钥对每个文件哈希的签名，只读取一次并按验证结果安装；未签名的版本需要管理员提示 |
| 会话代理 | 本地进程冒充助手或代理，以 SYSTEM 身份注入输入，或向它们提供媒体让其解码 | 管道名称随机且以第一个实例创建，DACL 只允许 SYSTEM，双方检查对方的进程 ID；两者都不解码远程媒体 |
| 剪贴板中的文件 | 对端在接收文件夹之外写入、覆盖文件、塞满磁盘，或让助手以 SYSTEM 身份读取文件 | `files` 权限；检查每个路径（不允许 `..`、绝对路径、保留名称或设备），只以新文件写入会话的文件夹，会话结束时删除；每次提供最多 1000 项、1 GiB，在两端以及接收时都检查；助手以控制台用户的身份读写，从不解释这些字节 |
| 被控端用户的控制权 | 控制端用输入阻止或隐私模式把他们挡在外面 | 两者都需要 `control-input`，随会话结束而解除，被控端用户可用 Ctrl+Alt+Shift+Esc（由阻止自己的钩子识别）或 Ctrl+Alt+Del（永远无法被钩取）解除；Ctrl+Alt+Del 只由助手发送，允许服务发送的策略只在调用期间打开 |

不在范围内：以同一用户身份运行的恶意软件（它本来就能操作桌面）、坐在已解锁桌面前的人，以及被攻破的服务商。

## 已知限制

- 在没有可用凭据存储（或其被锁定）的电脑上，身份不会持久化。
- 任何人在已解锁的桌面上都能显示和复制临时密码；托盘从不显示它。
- 知道密码的设备无需任何人确认即可获得密码授予的权限；在“权限”中关闭这些权限（或更换密码）能把它挡在外面。不知道密码的设备仍可发起请求，
  由确认与速率限制拦住。
- AI 任务会把屏幕发送给被控端用户所选的服务商，包括其他应用显示的内容；批准方式与本地输入是纵深防御，并不能识别所有敏感操作。
