# 安全

## 机密存储

- 核心把所有机密放在一个 JSON 映射中，用 XChaCha20-Poly1305（24 字节随机 nonce，附加数据 `kyokai/secrets/v1`）加密后
  原子写入 `secrets.bin`。
- 32 字节主密钥来自操作系统：Windows 上为当前用户的 DPAPI 数据块（`master.key`），macOS 上为登录钥匙串中的通用密码
  （服务 `com.yuanzhe.kyokai`，账户 `master-key` 或 `master-key.<profile>`）。
- 系统凭据存储不可用时不持久化任何内容：机密只在本次运行的内存中，界面会说明设备 ID 将改变。已存在但无法解密的存储
  从不被覆盖；本次运行使用临时身份并说明这一点。
- 机密在释放时清零；`kyokai_stop` 会全部丢弃。
- 存储中保存设备密钥、含网络密钥的网络设置（[networking.md](networking.md)）、OPAQUE 服务器密钥与固定密码的记录、受信任设备、
  已知被控端（[identity-and-access.md](identity-and-access.md)）以及 AI 服务商的 API 密钥。本地 API 只把网络密钥从界面（或
  `ctl`）传给引擎，从不回传；`ctl` 从环境变量而不是命令行读取它。固定密码与连接时输入的密码同样如此（`KYOKAI_PERMANENT_PASSWORD`、
  `KYOKAI_PASSWORD`）；核心只在该会话结束前把用户输入的密码保留在内存中，随后将其清零。
  服务商密钥同样如此传递（`ctl ai-key` 使用 `KYOKAI_AI_KEY`），且从不返回。

## AI 任务

- 模型使用被控端的服务商账户：密钥只经 HTTPS 发给该服务商，绝不进入日志、错误信息、状态、历史或其他设备。
- 截图只在任务对话期间存在于内存中，只发给所选的服务商；历史（`ai-tasks.json`）保存指令、模型的文字与操作，绝不保存图片。
  Kyokai 自己的窗口不参与采集（`SetContentProtection`），因此 AI 页面与批准提示不会到达模型。
- 模型的提议只能是输入：每个操作都要经过解析、对照最近一张截图检查范围，并由被控端自己的执行器执行；不会运行任何命令或代码，
  Kyokai 窗口拥有焦点时也不会注入任何输入。
- 本地输入、暂停、取消与紧急停止会立即收回任务的输入租约；之后才到达的响应绝不会执行（[computer-use.md](computer-use.md)）。

## 设备身份

- 一把 Ed25519 签名密钥，由系统随机源生成，保存在机密存储中。
- 设备 ID 由公钥推导：对 `kyokai/device-id/v1` 与公钥做 SHA-256，取前 8 字节为数，再归约到 100 000 000–999 999 999。
  它用于定位设备，从不证明设备身份。指纹（公钥的 SHA-256）才是完整身份。

## 临时密码

从 `abcdefghijkmnpqrstuvwxyz23456789`（不含 0、1、l、o）中取 8 个符号，约 40 位，来自系统随机源。它只存在于核心内存中，
每次启动和按需更换，只有用户显示或复制时才传给界面；一个随机序号告诉界面它已变化而不泄露它。

## 日志

日志记录版本、设备 ID 与机密的保存方式——从不记录密码、密钥或机密。引擎在状态目录写入 `logs/engine.log`。

## 本地 API

只服务引擎自己的用户（依据对端凭据，从不依据请求内容）；见 [architecture.md](architecture.md)。

## 已知限制

- 在没有可用凭据存储（或其被锁定）的电脑上，身份不会持久化。
- 任何人在已解锁的桌面上都能显示和复制临时密码；托盘从不显示它。
- AI 任务会把屏幕发送给被控端用户所选的服务商，包括其他应用显示的内容；批准方式与本地输入是纵深防御，并不能识别所有敏感操作。
